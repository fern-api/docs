---
title: Self-hosted generation
description: Run CLI generation on your own machine using Docker instead of Fern's cloud infrastructure.
---

By default, `fern generate` [runs the CLI generator on Fern's cloud infrastructure](/learn/cli-generator/get-started/quickstart). Pass `--local` to run generation on your own machine instead. No API definition data leaves your machine: the only network calls are pulling the Docker image (if not cached) and, when a Fern token is available, organization verification. This suits organizations with strict security or compliance requirements that need to keep their spec off Fern's infrastructure.

## Comparison with cloud generation

| | Cloud (default) | Local (`--local`) |
| --- | --- | --- |
| Infrastructure | Fern-managed | Your machine (Docker) |
| Network calls | Spec + config sent to Fern | Image pull, plus org verification when a token is set |
| Output options | GitHub repo (release/push mode) | Local file system or GitHub repo |
| Auth required | `FERN_TOKEN` or interactive login | None for local file system output; `FERN_TOKEN` or `fern login` for GitHub output |
| Docker required | No | Yes |

## Prerequisites

- [Fern CLI](https://www.npmjs.com/package/fern-api) v5.37.9 or later (`npm install -g fern-api`)
- [Docker](https://docs.docker.com/get-docker/) running on your machine
- [Rust toolchain](https://rustup.rs/) (stable) for building the generated output
- A `FERN_TOKEN` if you output to a GitHub repository (optional for local file system output; generate one with `fern token` or from the [Dashboard](/learn/dashboard/configuration/api-keys))

## Setup

<Info>
This page assumes you've completed the [Quickstart](/learn/cli-generator/get-started/quickstart), so the `cli` target in `sdk-config.yml` already writes to a [local `output.path`](/learn/cli-generator/get-started/configuration#output-and-distribution). Adding `--local` runs that same configuration through Docker instead of Fern's cloud.
</Info>

<Steps>

<Step title="Set your Fern token (optional)">

Local file system output doesn't require a token. When a token is set, the CLI verifies your organization and applies its settings, such as white-labeling, to the generated output. Generate a token with `fern token` or from the [Fern Dashboard](/learn/dashboard/configuration/api-keys), then export it:

```bash
export FERN_TOKEN=<your-token>
```

</Step>

<Step title="Run local generation">

```bash
fern generate --target cli --local
```

The CLI pulls the generator's Docker image (cached after the first run), processes your OpenAPI spec, and writes a complete Rust project to the configured output path.

</Step>

<Step title="Build and run">

```bash
cd ../my-cli
cargo build
./target/debug/my-cli --help
```

</Step>

</Steps>

## Custom container registry

`--local` pulls the generator image from Docker Hub. `sdk-config.yml` has no setting for a private registry; to pull from one, use a [`generators.yml` `image` configuration](/learn/cli-generator/legacy/get-started/local-generation#custom-container-registry).
