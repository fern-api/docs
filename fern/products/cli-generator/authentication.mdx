---
title: Authentication
description: Configure how generated CLIs authenticate with your API using flags, environment variables, a .env file, or the OS keyring.
---

Each generated CLI reads authentication credentials from the security schemes declared in your OpenAPI spec and the auth schemes in `api.auth` of `sdk-config.yml`. Credentials can come from a flag, an environment variable, or the credential store that `auth login` writes to.

Without a credential, the CLI still works: you can explore the command tree and view help.

## Credential sources

A flag wins over its environment variable, and both win over a stored credential. A [`.env` file](/learn/cli-generator/get-started/features#runtime-settings) can also set the environment variable.

| Scheme | Flags | Environment variables |
| --- | --- | --- |
| Bearer, OpenID Connect | `--token` | `<NAME>_TOKEN` |
| API key in a header | `--api-key` | `<NAME>_API_KEY` |
| Basic | `--username`, `--password` | `<NAME>_USERNAME`, `<NAME>_PASSWORD` |
| OAuth 2 client credentials | `--client-id`, `--client-secret` (or `--token` to skip the exchange) | `<NAME>_CLIENT_ID`, `<NAME>_CLIENT_SECRET` |

`<NAME>` is the binary name uppercased, with hyphens mapped to underscores. An environment variable named on a scheme in [`api.auth`](/learn/sdks/reference/sdk-config#apiauth) replaces the default name.

```bash
# CLI flag takes priority
box users get-current-user --api-key sk-123

# Otherwise falls back to the environment variable
export BOX_API_KEY=sk-123
box users get-current-user
```

## Supported auth schemes

| Scheme | How the CLI applies it |
| --- | --- |
| Bearer (`http: bearer`) | Sends `Authorization: Bearer <token>`. A `prefix` on the scheme in `api.auth.schemes` replaces `Bearer`. |
| API key (`apiKey`, in a header) | Sends the key in the configured header (for example, `X-Auth-Token`). A `prefix` on the `api-key` scheme in `api.auth.schemes` is prepended at request time, so the stored credential stays the bare key. |
| Basic (`http: basic`) | Sends `Authorization: Basic <base64(user:pass)>`. |
| OAuth 2 client credentials | Exchanges the client ID and secret for a token, configured with the same [`api.auth` fields the SDKs use](/learn/sdks/reference/sdk-config#apiauth). |
| OpenID Connect | Sends the token as a bearer token. |

The CLI uses the first scheme of each kind. API keys sent in a query parameter or cookie aren't supported, and the generator skips them with a warning.

An operation that requires authentication fails locally with an auth error (exit code `2`) when no flag, environment variable, or stored credential supplies one, and the request isn't sent. Operations with `security: []`, an optional (`- {}`) alternative, or no declared security are sent as-is.

## Log in and out

Every generated CLI has an `auth` command group that stores credentials between runs:

```bash
my-cli auth login     # store a credential
my-cli auth status    # show where each credential comes from
my-cli auth logout    # remove stored credentials
```

| Flag | Command | Effect |
| --- | --- | --- |
| `--with-token` | `login` | Read the credential from stdin, one value per line. |
| `--from-env` | `login` | Store the credential the flags and environment give. |
| `--scheme <SCHEME>` | `login`, `logout` | Pick the credential when the CLI takes several. `logout` without it removes every stored credential. |
| `--no-verify` | `login` | Store the credential without checking it. |

By default, `login` checks the credential with a read-only `GET` request that takes no arguments and stores nothing the API rejects. The group is named `auth` unless the API already has a command of that name.

Credentials go to the OS keyring: the macOS Keychain, the Windows Credential Manager, or the Linux secret service. Set `<NAME>_CREDENTIAL_STORE=file` to store them in a file readable only by the owner instead; the CLI doesn't fall back to a file on its own. Builds without a keyring, such as static Linux builds, require the file store.
