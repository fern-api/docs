## `profiles set` confirms before creating a profile

<ChangelogTags>auth</ChangelogTags>

`profiles set <name>` no longer creates a missing profile without asking, so a mistyped name can't save credentials to a new, unintended profile. In a terminal it asks first, offering a similarly named existing profile before asking whether to create the new one; declining writes nothing. When stdin or stderr isn't a terminal, `set` on a missing profile fails with a hint instead of creating it. Scripts that relied on `set` to create profiles need the new `--yes` / `-y` flag or a `profiles create` call first. Updating an existing profile is unchanged.
