---
title: Custom commands
description: Add your own Rust commands to a generated CLI, such as workflows that chain API calls, shortcuts, and local utilities.
---

Custom commands are subcommands you write in Rust and compile into the generated CLI alongside the commands derived from your API spec. Use them for anything that doesn't map to a single endpoint: a workflow that chains several API calls, a shortcut for a common task, or a local utility such as verifying a webhook signature.

Custom commands get the same SDK client the generated commands use, with the credentials from flags, environment variables, and `auth login`. What a custom command returns is printed like a generated command's result, so `--format`, `--query`, and the error output work on it.

## Generated files

Custom command support is on by default. The generated repository is a Cargo workspace with the CLI crate in `cli/` and the Rust SDK crate beside it in `<binaryName>-sdk/`.

| Path | Description | Regenerated |
| --- | --- | --- |
| `cli/src/commands/custom/mod.rs` | Where you list your commands (`all()`) and hooks (`hooks()`) | No, when protected (see below) |
| `cli/src/commands/custom/*.rs` | Files you add for your commands | No |
| `.fernignore` | Lists the custom commands folder so regeneration leaves it alone | Yes |
| `.agents/skills/custom-commands/SKILL.md` | A guide for coding agents that uses your API's real command names | Yes |

With GitHub delivery, the generated `.fernignore` protects `cli/src/commands/custom/`. With `files` delivery, nothing reads `.fernignore`: list `cli/src/commands/custom/mod.rs` in `generation.ignoreFiles` of the CLI target instead.

<Tip>
Point a coding agent such as Claude Code at `.agents/skills/custom-commands/SKILL.md` to have it write custom commands for you.
</Tip>

## Add a command

<Steps>

<Step title="Write the command">

Add a file to `cli/src/commands/custom/` and build a `CustomCommand` from a [clap](https://docs.rs/clap) `Command` and a handler. The handler gets the SDK client and the command's argument matches, and returns what the CLI prints.

```rust title="cli/src/commands/custom/hello.rs"
use clap::Command;
use serde_json::json;

use crate::Output;
use crate::custom_command::CustomCommand;

pub fn hello() -> CustomCommand {
    CustomCommand::new(&[], Command::new("hello").about("Say hello"), |_client, _matches| {
        Box::pin(async move { Ok(Output::Json(json!({ "hello": "world" }))) })
    })
}
```

To call the API, add `use crate::Api;` and call its methods on the client, as the generated commands do.

</Step>

<Step title="List it in mod.rs">

```rust title="cli/src/commands/custom/mod.rs"
mod hello;

use crate::custom_command::CustomCommand;
use crate::hooks::Hooks;

pub fn all() -> Vec<CustomCommand> {
    vec![hello::hello()]
}

pub fn hooks() -> Hooks {
    Hooks::new()
}
```

</Step>

<Step title="Build and run it">

```bash
cargo build
./target/debug/plant hello
```

The new command shows up in `plant --help` next to the spec-derived commands.

</Step>

</Steps>

## Choose where the command appears

The first argument to `CustomCommand::new` names the groups the command sits in: `&[]` for a top-level command, `&["plants"]` for `plant plants <command>`. A missing group is created. A custom command with the same path as a generated one replaces it; `completion` and `man` can't be replaced.

| Method | Effect |
| --- | --- |
| `.hide_flags(&["format", "query"])` | Hides global flags from the command's help. The command still accepts them. |
| `.output(fields, columns)` | Declares the result's fields, which `--properties` can pick, and the `--format table` columns. |
| `.credentials(sets)` | Declares the credentials the command needs, in a CLI that checks credentials. |

Paginated custom commands can reuse the page flags in `crate::paging::PageArgs`.

To keep your own commands at the top level and the API commands under a single group, set `rootGroup` in the CLI target's `generation` block. With the following config, `plant plants list` becomes `plant api plants list`:

```yaml title="sdk-config.yml"
targets:
  - language: cli
    generation:
      binaryName: plant
      rootGroup: api
```

## Hooks

List hooks in `hooks()` to change what commands print or to answer for their errors. A path is the words of a command, where `*` stands for one word and `**` for any number of words. This example assumes the API has a `pets` command group with a `get` command:

```rust title="cli/src/commands/custom/mod.rs"
pub fn hooks() -> Hooks {
    Hooks::new()
        .transform_response(&["pets", "**"], |value, _path| Ok(value))
        .recover_error(&["pets", "get"], |_error, _path| None)
}
```

`transform_response` hooks run on the JSON of each matching command, in the order they were added. For `recover_error`, the first hook that returns `Some(value)` prints that value instead of the error. A hook whose path matches no command is rejected.

## Things to know

- **Your commands call regenerated code.** If a spec change renames an endpoint or resource, update your commands to match. `cargo build` reports every call that no longer exists.
- **You can turn custom commands off.** Set [`customCommands: false`](/learn/cli-generator/get-started/configuration#customcommands) to generate a spec-only CLI without the custom commands folder or the agent skill.
