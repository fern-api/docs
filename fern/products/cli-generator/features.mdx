Generated CLIs ship with a common set of runtime flags and environment variables: output formatting, pagination, request input, streaming, exit codes, and network settings. The binary name (set with [`binaryName`](/learn/cli-generator/get-started/configuration#binaryname)) determines the environment-variable prefix, written `<NAME>` below: the binary name uppercased, with hyphens mapped to underscores (for example, `CONTOSO`).

## Output formatting

Use the `--format` flag to control how responses are displayed. Without it, the CLI prints a table when stdout is a terminal and JSON when output is piped.

| Format | Flag | Description |
| --- | --- | --- |
| JSON | `--format json` | Indented in a terminal, on one line when piped. The default when output is piped. |
| Table | `--format table` | Columns for a list, keys and values for an object. The default in an interactive terminal. |
| YAML | `--format yaml` | YAML representation of the response (also accepts `yml`). |
| CSV | `--format csv` | Comma-separated values, one row per item. |
| JSON Lines | `--format jsonl` | One JSON line per item (also accepts `ndjson`). |
| Raw | `--format raw` | The response as the SDK decoded it, on one line, with no formatting. |

| Flag | Effect |
| --- | --- |
| `--human` | Print a table even when output is piped. |
| `--quiet` | Print nothing when the command succeeds. |
| `--query <EXPR>` | Select part of the response with a [JMESPath](https://jmespath.org/) expression. |
| `--properties <FIELDS>` | Print only the named output fields. `--help` lists each command's output fields. |

Table columns follow [`x-fern-cli-table`](/learn/cli-generator/get-started/openapi-extensions#table-columns) when the operation declares it.

```bash
# Display plants in a table
contoso plants list --format table

# Export orders as CSV
contoso orders list --format csv > orders.csv

# Print only the names
contoso plants list --query '[].name'
```

## Pagination

For endpoints annotated with [`x-fern-pagination`](/learn/api-definitions/openapi/extensions/pagination), the CLI fetches every page when the `--page-all` flag is set.

| Flag | Description | Default |
| --- | --- | --- |
| `--page-all` | Fetch every page and print each as it arrives (as JSON, one line per page). | Off |
| `--page-limit <N>` | Maximum number of pages to fetch. | 10 |
| `--page-delay <MS>` | Delay in milliseconds between page requests. | 100 |
| `--no-pager` | Skip the pager in an interactive terminal. | Off |

In a terminal, paged output goes through the program in `<NAME>_PAGER`, else `PAGER`, else `less`. These flags are registered only on operations whose spec declares pagination.

```bash
# Fetch all plants, one JSON line per page
contoso plants list --page-all

# Limit to 5 pages with a 200 ms delay
contoso plants list --page-all --page-limit 5 --page-delay 200
```

## Passing parameters

Path, query, and header parameters can be passed as individual flags or as a single JSON object. Request bodies use `--json`.

| Flag | Purpose |
| --- | --- |
| `--<param>` | An individual parameter, kebab-cased from its name in the spec. Typed flags check enum values, lists, and models. |
| `--params <JSON>` | Path, query, and header parameters as one JSON object keyed by the spec's parameter names. Wins over individual flags. |
| `--json <JSON>` | The JSON request body. Pass `-` to read it from stdin. |

```bash
# Individual flags
contoso plants get --plant-id abc

# The equivalent --params JSON object
contoso plants get --params '{"plantId": "abc"}'

# Request body
contoso plants create \
  --json '{"name": "Monstera", "species": "Monstera deliciosa", "sunlight": "indirect"}'
```

List flags take repeated values or a JSON array, so `--ids 1 --ids 2` and `--ids '[1,2]'` are equivalent. Inputs are checked against the spec before the request is sent; a missing required parameter fails with a validation error (exit code `3`).

Run `contoso <command> --help` to list a command's flags. Add `--format json` (`contoso plants list --help --format json`) to print the same help as JSON for agents and scripts.

## Request and response bodies

| Body | How the CLI handles it |
| --- | --- |
| Text or binary request body | `--body` takes a file path, stdin, or base64-encoded input. |
| `multipart/form-data` request body | One flag per form part. |
| File response | `-o`/`--output <PATH>` saves the response to a file, or `-` for stdout. |
| Server-sent events | Events print as they arrive. `--no-stream` buffers the whole stream. |

## Exit codes

| Code | Meaning | Example cause |
| --- | --- | --- |
| `0` | Success | Command completed normally. |
| `1` | API error | Server returned a 4xx/5xx response. |
| `2` | Auth error | [Credentials](/learn/cli-generator/get-started/authentication) missing or invalid. |
| `3` | Validation error | Bad arguments, unknown command, or invalid JSON. |
| `4` | Discovery error | Reserved for compatibility with the Legacy CLI generator. The CLI doesn't exit with it. |
| `5` | Internal error | Unexpected failure. |

Errors go to stderr: a JSON object by default, or a line for a person with `--format table` or `--human`. The JSON object includes the error's `kind`, whether it's `retryable`, and, for validation errors, the `missing` inputs. Run `contoso errors` to list the exit codes.

## Runtime settings

| Setting | Flag | Environment variable |
| --- | --- | --- |
| Base URL | `--base-url` | `<NAME>_BASE_URL` |
| User-Agent suffix | `--user-agent-suffix` | `<NAME>_USER_AGENT_SUFFIX` |
| Request timeout, in whole seconds | — | `<NAME>_TIMEOUT_SECS` |

A User-Agent suffix is appended after the SDK's `User-Agent` header, so a tool built on top of the CLI can add its own product token. The flag wins over the environment variable.

```bash
contoso plants list --user-agent-suffix "partner-app/3.1"

export CONTOSO_TIMEOUT_SECS=45
contoso plants list
```

Headers declared API-wide with [`x-fern-global-headers`](/learn/api-definitions/openapi/extensions/global-headers) are sent on every request. Each header resolves from its hidden flag, then its environment variable, then its default; a required header with no value fails before the request is sent.

At startup, the CLI reads the first `.env` file found from the working directory upwards and sets each variable the environment doesn't already have. Variables that redirect traffic or weaken transport security, such as `HTTPS_PROXY` and `<NAME>_BASE_URL`, are ignored in a `.env` file.

## Shell completion and man pages

Every generated CLI has `completion` and `man` commands, which print a shell completion script and a man page. When a spec tag clashes with a built-in command name (`completion`, `man`, or `errors`), the generator renames the tag's command group. The `auth` group takes another name when the API already has an `auth` command.
