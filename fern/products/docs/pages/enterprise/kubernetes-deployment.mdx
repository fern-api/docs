This guide covers deploying self-hosted Fern documentation to Kubernetes. The examples work with Docker Desktop with Kubernetes enabled, AWS EKS, GKE, or any other Kubernetes cluster.

## Prerequisites

Before deploying to Kubernetes, ensure you have:
- Completed the [self-hosted setup](/learn/docs/self-hosted/set-up) and built your custom Docker image
- A Kubernetes cluster (Docker Desktop, EKS, GKE, etc.)
- `kubectl` configured to use your cluster

## Deployment configuration

Create a `deployment.yaml` file to define your Kubernetes Deployment:

```yaml deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: fern-docs
  labels:
    app: fern-docs
spec:
  replicas: 1
  selector:
    matchLabels:
      app: fern-docs
  template:
    metadata:
      labels:
        app: fern-docs
    spec:
      securityContext:
        runAsNonRoot: true
        runAsUser: 65532
        runAsGroup: 65532
        fsGroup: 65532
        fsGroupChangePolicy: OnRootMismatch
      containers:
        - name: fern-docs
          image: your-registry/fern-docs:latest
          imagePullPolicy: IfNotPresent
          ports:
            - name: docs
              containerPort: 3000
              protocol: TCP
            - name: health
              containerPort: 8081
              protocol: TCP
          env:
            - name: WARMUP
              value: "false"
            - name: FERN_LOG_LEVEL
              value: "info"
            - name: TMPDIR
              value: /tmp
          resources:
            requests:
              memory: "2Gi"
              cpu: "1000m"
            limits:
              memory: "4Gi"
              cpu: "2000m"
          livenessProbe:
            httpGet:
              path: /liveness
              port: 8081
            initialDelaySeconds: 120
            periodSeconds: 10
            timeoutSeconds: 5
            failureThreshold: 3
          readinessProbe:
            httpGet:
              path: /readiness
              port: 8081
            initialDelaySeconds: 60
            periodSeconds: 5
            timeoutSeconds: 5
            failureThreshold: 6
          securityContext:
            allowPrivilegeEscalation: false
            runAsNonRoot: true
            runAsUser: 65532
            runAsGroup: 65532
            privileged: false
            readOnlyRootFilesystem: false
            capabilities:
              drop:
                - ALL
      terminationGracePeriodSeconds: 30
```

Replace `your-registry/fern-docs:latest` with your actual image name.

## Service configuration

Create a `service.yaml` file to expose your deployment:

```yaml service.yaml
apiVersion: v1
kind: Service
metadata:
  name: fern-docs
  labels:
    app: fern-docs
spec:
  type: NodePort
  ports:
    - name: http
      port: 80
      targetPort: 3000
      protocol: TCP
      nodePort: 30080
  selector:
    app: fern-docs
```

For Docker Desktop, this configuration makes the documentation accessible at `http://localhost:30080`.

## Deploy to your cluster

Apply the configuration files to your cluster:

```bash
kubectl apply -f deployment.yaml
kubectl apply -f service.yaml
```

Wait for the pod to be ready (this may take 1-2 minutes):

```bash
kubectl get pods -w -l app=fern-docs
```

Get the service URL:

```bash
kubectl get service fern-docs
```

## Configuration options

### Environment variables

| Variable | Description | Default |
|----------|-------------|---------|
| `WARMUP` | Enable cache warmup on startup | `false` |
| `FERN_LOG_LEVEL` | Log level (debug, info, warn, error) | `info` |
| `TMPDIR` | Temporary directory for the container | `/tmp` |

### Resource requirements

Adjust the resource configuration based on your documentation size and expected traffic:

```yaml
resources:
  requests:
    memory: "2Gi"
    cpu: "1000m"
  limits:
    memory: "4Gi"
    cpu: "2000m"
```

### Health checks

The deployment includes liveness and readiness probes on port 8081:

- **Liveness probe** (`/liveness`): Checks if all service processes are running
- **Readiness probe** (`/readiness`): Checks if all services are ready to serve traffic

The probes are configured with appropriate delays to account for the container's startup time. See [Health check endpoints](/learn/docs/self-hosted/health-check-endpoints) for more details.

## Scaling

For production deployments, scale the deployment:

```bash
kubectl scale deployment fern-docs --replicas=3
```

## Ingress configuration

For production, use an Ingress instead of a NodePort service:

```yaml ingress.yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: fern-docs
  annotations:
    nginx.ingress.kubernetes.io/proxy-body-size: "50m"
spec:
  ingressClassName: nginx
  rules:
    - host: docs.example.com
      http:
        paths:
          - path: /
            pathType: Prefix
            backend:
              service:
                name: fern-docs
                port:
                  number: 80
```

## Troubleshooting

### Pod stuck in Pending state

Check if there are resource constraints:

```bash
kubectl describe pod -l app=fern-docs
```

### Pod crashes or restarts

Check the logs:

```bash
kubectl logs -l app=fern-docs --tail=100
```

### Readiness probe failing

The container takes 2-3 minutes to fully start. Check the readiness status:

```bash
kubectl get pods -l app=fern-docs -o wide
kubectl exec -it <pod-name> -- curl http://localhost:8081/readiness
```
