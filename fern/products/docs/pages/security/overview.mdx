Fern's documentation platform is designed with security as a core principle. This page addresses common security concerns from enterprise security teams evaluating Fern for their documentation needs.

## Data storage and privacy

Fern does not persist or store user-sensitive information on our servers. When authentication features like [API key injection](/learn/docs/api-references/autopopulate-api-key) or [RBAC](/learn/docs/authentication/rbac) are enabled, user credentials and tokens are handled exclusively through browser cookies.

These cookies are:
- Stored only in the user's browser
- Never transmitted to or stored on Fern's backend infrastructure
- Managed entirely client-side for security and privacy
- Automatically cleared when the user logs out or the session expires

This architecture ensures that Fern never has access to your users' credentials or API keys, even when providing authentication features.

## Open-source transparency

Fern's documentation frontend is open-source, allowing your security team to audit the code that handles user credentials and authentication.

You can review:
- How cookies are stored and accessed
- How API keys are injected into code examples
- How authentication tokens are handled
- The complete client-side authentication flow

The open-source nature of Fern means there are no hidden processes or black boxes when it comes to credential handling. Your security team can verify that user data is handled according to your security policies.

## Self-hosted deployments

For organizations with strict security requirements, Fern offers [self-hosted deployments](/learn/docs/enterprise/self-hosted) that allow you to run the entire documentation platform on your own infrastructure.

Self-hosting provides:
- Complete control over where documentation is hosted
- No external dependencies on Fern's infrastructure
- Full data sovereignty and compliance with internal security policies
- Ability to operate in air-gapped or restricted network environments

With self-hosting, all documentation assets, authentication flows, and user interactions occur entirely within your infrastructure.

<Note>
Self-hosting is only recommended for organizations with strict security requirements or those that need to operate in air-gapped or restricted network environments.
</Note>

## Implementation recommendations

When implementing Fern's authentication features, we recommend:

- **Use HTTPS**: Always serve your documentation over HTTPS to protect credentials in transit
- **Configure secure cookies**: Ensure authentication cookies use the `Secure` and `HttpOnly` flags
- **Implement token expiration**: Set appropriate expiration times for authentication tokens
- **Regular security audits**: Review your authentication implementation and Fern's open-source code periodically
