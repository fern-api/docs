---
title: Bring your custom domain
description: Configure DNS records to serve your Fern documentation site from a custom subdomain, subpath, or root domain.
---


You can configure any of the following custom domain types:
- **Subdomain**: `docs.mydomain.com`
- **Subpath**: `mydomain.com/docs`
- **Root domain**: `mydomain.com`

Fern recommends [using the Fern Dashboard to set up custom domains](/learn/dashboard/configuration/custom-domains). The Dashboard automatically provides the correct DNS records based on your domain type. If you prefer to configure your domain manually, follow the instructions on this page. 

## Manual setup

Expand the section below that matches your domain type:

<AccordionGroup>
<Accordion title="Subdomain">

To host your documentation on a subdomain like `docs.mydomain.com`:

<Steps>
<Step title="Update `docs.yml`">

Add your `custom-domain` and merge your changes into `main`. [Here's an example](https://github.com/octoml/fern-config/blob/389b67679953856ba0716537981a6d749635556f/fern/docs.yml#L1-L3).

```yaml docs.yml
instances:
 - url: example.docs.buildwithfern.com
   custom-domain: docs.mydomain.com
```

Then run `fern generate --docs` to publish.
</Step>

<Step title="Verify domain ownership">

In the [Fern Dashboard](https://dashboard.buildwithfern.com/), navigate to your docs site and select **Add Custom Domain**. The Dashboard displays a TXT record to verify you own the domain:

| Type | Host | Value |
|------|------|-------|
| TXT | `_fern-verification.mydomain.com` | `fern-verify=<value from Dashboard>` |

Add this record at your domain registrar. If the apex domain is already linked to another Vercel account, the Dashboard also requires a Vercel ownership TXT record:

| Type | Host | Value |
|------|------|-------|
| TXT | `_vercel.mydomain.com` | Provided by Dashboard |

After adding the records, click **Verify Ownership** in the Dashboard. Verification completes once both the Fern TXT and the Vercel ownership check pass.
</Step>

<Step title="Configure DNS">

Add a CNAME record at your domain registrar:

| Type | Host | Value |
|------|------|-------|
| CNAME | `docs` | `cname.vercel-dns.com` |

Replace `docs` with your chosen subdomain.

<Warning title="Cloudflare users">
  If you use Cloudflare, disable proxying (set the record to DNS-only) so Vercel can issue an SSL certificate.
</Warning>
</Step>

<Step title="Verify the setup">

SSL is provisioned automatically after verification. DNS propagation can take up to 10 minutes; the Dashboard polls liveness and shows the domain as active when ready.

<Tip>Access your docs site from an incognito browser or mobile device to confirm.</Tip>
</Step>

</Steps>
</Accordion>

<Accordion title="Subpath">

<Markdown src="/snippets/team-plan.mdx"/>

To host your documentation on a subpath like `mydomain.com/docs`:

<Steps>
<Step title="Configure the `url` in `docs.yml`">

Append the subpath to the end of the `url`. This example uses `docs`, but you can use any path segment such as `reference` or `developer`.

<CodeBlock title="docs.yml">
```yaml
instances:
  - url: example.docs.buildwithfern.com/docs
```
</CodeBlock>
</Step>

<Step title="Configure the `custom-domain`">

Below the `url`, add a `custom-domain` key:

<CodeBlock title="docs.yml">
```yaml
instances:
  - url: example.docs.buildwithfern.com/docs
    custom-domain: mydomain.com/docs
```
</CodeBlock>

[Here's an example.](https://github.com/fern-api/fern/blob/7d8631c6119787a8aaccb4ba49837e73c985db28/fern/docs.yml#L1-L3)

Then run `fern generate --docs` to publish.
</Step>

<Step title="Verify domain ownership">

In the [Fern Dashboard](https://dashboard.buildwithfern.com/), navigate to your docs site and select **Add Custom Domain**. Add the TXT records shown in the Dashboard to your domain registrar, then click **Verify Ownership**. You need a `_fern-verification` TXT record and, if the apex is linked to another Vercel account, a `_vercel` TXT record.
</Step>

<Step title="Set up a reverse proxy">

A subpath can't be routed with DNS alone — your infrastructure must forward requests from `mydomain.com/docs` to Fern's origin with the `x-fern-host` header set to your bare domain. Follow the [reverse proxy setup instructions](/learn/docs/preview-publish/reverse-proxy) for your provider (Cloudflare Workers, AWS CloudFront, Netlify, Vercel, Nginx, Akamai, or Caddy).
</Step>

<Step title="Verify the setup">

SSL is provisioned automatically after verification. Propagation can take up to 10 minutes. Access your docs site from an incognito browser or mobile device to confirm.

<Warning title="HTTP/2 transfer errors with nginx">
If you see partial page loads or HTTP/2 transfer errors, nginx's lack of native [Brotli](https://github.com/google/brotli) support may be the cause. Fern's CDN serves Brotli-compressed responses by default, which nginx can't decode when proxying upstream.

Add this directive to your nginx config to request only supported encodings:

```nginx
proxy_set_header Accept-Encoding "gzip,deflate";
```
</Warning>
</Step>

</Steps>

</Accordion>
<Accordion title="Root domain">

To host your documentation on a root domain like `mydomain.com`:

<Steps>
<Step title="Update `docs.yml`">

<CodeBlock title="docs.yml">
```yaml
instances:
  - url: example.docs.buildwithfern.com
    custom-domain: www.mydomain.com
```
</CodeBlock>

[Here's an example.](https://github.com/dannysheridan/katiedanny/blob/2fcf5769e2994af29e31d00904e04788b188a18b/fern/docs.yml#L3-L5)

Then run `fern generate --docs` to publish.
</Step>

<Step title="Verify domain ownership">

In the [Fern Dashboard](https://dashboard.buildwithfern.com/), navigate to your docs site and select **Add Custom Domain**. The Dashboard displays TXT records to verify you own the domain:

| Type | Host | Value |
|------|------|-------|
| TXT | `_fern-verification.mydomain.com` | `fern-verify=<value from Dashboard>` |

If the apex is linked to another Vercel account, the Dashboard also requires a Vercel ownership TXT:

| Type | Host | Value |
|------|------|-------|
| TXT | `_vercel.mydomain.com` | Provided by Dashboard |

Add these records at your domain registrar, then click **Verify Ownership** in the Dashboard.
</Step>

<Step title="Configure DNS">

Add the following records at your domain registrar:

| Type | Host | Value |
|------|------|-------|
| CNAME | `www` | `cname.vercel-dns.com` |
| A | `@` | `76.76.21.21` |

The CNAME handles `www.mydomain.com`; the A record routes the apex `mydomain.com` to `www.mydomain.com`.
</Step>

<Step title="Verify the setup">

SSL is provisioned automatically after verification. DNS propagation can take up to 10 minutes; the Dashboard polls liveness and shows the domain as active when ready.

<Tip>Access your docs site from an incognito browser or mobile device to confirm.</Tip>
</Step>

</Steps>
</Accordion>
</AccordionGroup> 

## Troubleshooting

### Vercel error page after pointing DNS

A Vercel error page with an error ID like `cdg1::...` (often `DEPLOYMENT_NOT_FOUND`) means DNS is pointing to Vercel but domain ownership verification has not completed. To resolve:

1. Confirm both TXT records are in place: the `_fern-verification` record and, if required, the `_vercel` ownership record.
2. Wait for DNS propagation (up to 10 minutes).
3. Return to the [Fern Dashboard](https://dashboard.buildwithfern.com/) and click **Verify Ownership** again.

### SSL certificate not provisioning

SSL certificates are issued automatically after DNS is verified. If the certificate doesn't appear within 10 minutes:
- Confirm the CNAME or A record values are correct.
- If using Cloudflare, disable proxying (set the record to DNS-only) so Vercel can issue the certificate.

<llms-only>
### Common errors

Errors below are surfaced by `fern check` and `fern generate --docs` when validating the `instances[].url` values in `docs.yml`.

#### Invalid URL format: "X". Expected format: \<subdomain\>.docs.buildwithfern.com

The `url` is missing a subdomain or uses an unexpected shape. Use `<your-org>.docs.buildwithfern.com` (for example, `plantstore.docs.buildwithfern.com`). Don't include `https://`.

#### Invalid domain in URL "X". The URL must end with one of: docs.buildwithfern.com, docs.dev.buildwithfern.com

The `url` doesn't end with a supported Fern domain. Update the `url` to end with `docs.buildwithfern.com`. Configure your vanity domain with [`custom-domain`](#multiple-custom-domains).

#### Invalid URL "X". A subdomain is required before docs.buildwithfern.com

The `url` is set to the bare domain. Add a subdomain prefix such as `<your-org>.docs.buildwithfern.com`.
</llms-only>

### Multiple custom domains

To serve your documentation from multiple custom domains (e.g., for partner or white-label deployments), follow the above steps for each domain (subdomain, subpath, or root domain), then configure an array in your `docs.yml`:

```yaml docs.yml
instances:
  - url: example.docs.buildwithfern.com
    custom-domain:
      - www.mydomain.com
      - partner.otherdomain.com
```

Complete domain verification in the Dashboard for each domain before configuring DNS.
