# Stainless Docs vs Fern Docs: Quick comparison

<Info title="TL;DR">
**Fern Docs** is production-ready and enterprise-grade with comprehensive features. **Stainless Docs** is in early access with significant feature gaps for enterprise deployments.
</Info>

---

## Top 10 enterprise gaps where Stainless falls short

<CardGroup cols={2}>
  <Card title="1. Platform maturity" icon="triangle-exclamation">
    **Stainless**: Early access, "expect breaking changes before 1.0"
    
    **Fern**: Production-ready, stable, widely deployed
    
    **Impact**: Stainless not suitable for mission-critical documentation
  </Card>

  <Card title="2. Fern Editor & non-technical authors" icon="users">
    **Stainless**: Git-only workflow, requires technical expertise
    
    **Fern**: WYSIWYG Fern Editor + GitHub App for writers/PMs
    
    **Impact**: Stainless limits collaboration to engineers only
  </Card>

  <Card title="3. RBAC & audience filtering" icon="shield-halved">
    **Stainless**: No documented support
    
    **Fern**: Content gating by audience (internal vs. public, by tier)
    
    **Impact**: Can't show different docs to different user groups
  </Card>

  <Card title="4. API versioning" icon="code-branch">
    **Stainless**: No documented versioning system
    
    **Fern**: First-class versioning with availability states
    
    **Impact**: Can't maintain multiple API versions simultaneously
  </Card>

  <Card title="5. Interactive API explorer" icon="play-circle">
    **Stainless**: No documented playground
    
    **Fern**: Full API testing with auto-populated credentials, WebSocket support
    
    **Impact**: Developers must use external tools (Postman, curl)
  </Card>

  <Card title="6. Enterprise SSO" icon="key">
    **Stainless**: API keys for their service only
    
    **Fern**: WorkOS integration (SAML/OIDC/SCIM)
    
    **Impact**: Can't require authentication for viewing docs
  </Card>

  <Card title="7. Full-stack self-hosting" icon="server">
    **Stainless**: Static files only
    
    **Fern**: Complete Docker container (DB, storage, search, UI)
    
    **Impact**: Not suitable for regulated industries requiring on-prem
  </Card>

  <Card title="8. AI operational controls" icon="robot">
    **Stainless**: Basic RAG search
    
    **Fern**: Guidance docs, Documents API, Slack bot, MCP server, analytics
    
    **Impact**: Can't control AI answers or add custom knowledge sources
  </Card>

  <Card title="9. Multi-spec support" icon="file-code">
    **Stainless**: OpenAPI + Stainless config only
    
    **Fern**: OpenAPI, AsyncAPI, gRPC, OpenRPC, Fern spec
    
    **Impact**: Limited to REST APIs, no event-driven or RPC support
  </Card>

  <Card title="10. Advanced redirects & SEO" icon="arrow-right-arrow-left">
    **Stainless**: No documented redirect system
    
    **Fern**: 299+ redirect rules with pattern matching
    
    **Impact**: Difficult to migrate or restructure large sites
  </Card>
</CardGroup>

## When to choose each

<AccordionGroup>
  <Accordion title="Choose Fern when" defaultOpen={true}>
    <Success>Enterprise requirements (RBAC, SSO, versioning)</Success>
    <Success>Regulated industries (self-hosted required)</Success>
    <Success>Non-technical authors need to contribute</Success>
    <Success>Interactive API testing is important</Success>
    <Success>Production stability is critical</Success>
    <Success>Advanced AI with operational controls</Success>
    <Success>Large-scale documentation (100+ pages)</Success>
    <Success>Multi-product or multi-version APIs</Success>
  </Accordion>

  <Accordion title="Choose Stainless when">
    <Warning>Comfortable with early access software</Warning>
    <Warning>Simple docs without versioning/RBAC</Warning>
    <Warning>All authors are technical (Git comfortable)</Warning>
    <Warning>Static hosting is sufficient</Warning>
    <Warning>Astro expertise and preference</Warning>
    <Warning>Can wait for 1.0 stability</Warning>
  </Accordion>
</AccordionGroup>
