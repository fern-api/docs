This page is a sample used to exercise the Fern Docs build and publishing pipeline. It walks through the most common authoring patterns — frontmatter, headings, callouts, code blocks, tabs, accordions, and cross-page links — so that pull requests touching the docs infrastructure can be verified against a single, self-contained reference.

<Callout intent="info">
  This page is intentionally hidden from search engines (`noindex: true`) and lives in the hidden **Resources** section. It is safe to land, revert, or move without affecting customer-visible navigation.
</Callout>

## What this page verifies

- Frontmatter is parsed correctly and the page is reachable via the navigation entry in `fern/products/docs/docs.yml`.
- Internal links resolve using `/learn/...` URL paths derived from the YAML config, not relative file paths.
- Common MDX components render without errors during `fern docs generate` and on the deployed preview.
- Pre-commit hooks (Vale, link checks) accept a representative mix of prose and structured content.

## Frontmatter checklist

Every MDX page should ship with at least:

- `title` — appears in the browser tab and as the page heading.
- `description` — used for SEO and link previews.
- `slug` (optional) — overrides the auto-derived URL segment.
- `noindex` (optional) — set to `true` for internal or sample pages.

For the full list of supported fields, see the [page-level settings reference](/learn/docs/configuration/page-level-settings).

## Components

### Callouts

Callouts highlight tips, warnings, and notes. Use the intent that matches the content — `info`, `success`, `warning`, or `danger`.

<Callout intent="success">
  Use `success` callouts to confirm a positive outcome, like "Your docs site is now live at `your-domain.docs.buildwithfern.com`."
</Callout>

<Callout intent="warning">
  Use `warning` callouts for caveats that won't block a user but are easy to miss, like "Custom domains require a CNAME record before they will resolve."
</Callout>

### Code blocks

Code blocks support syntax highlighting and optional titles. Reach for them whenever a command or snippet is more than a few words.

```bash title="Install the Fern CLI"
npm install -g fern-api
fern --version
```

```yaml title="fern/docs.yml (excerpt)"
instances:
  - url: your-org.docs.buildwithfern.com

navigation:
  - section: Getting started
    contents:
      - page: Overview
        path: ./pages/getting-started/overview.mdx
```

### Accordions

Accordions hide secondary detail behind a click. Prefer them for FAQ-style content or progressive disclosure of advanced options.

<AccordionGroup>
  <Accordion title="Why is my page missing from the sidebar?">
    Fern only includes pages that are referenced in `docs.yml` navigation or auto-discovered by a `folder:` entry. If a page is not appearing, confirm that its `path:` matches the file on disk and that no parent section is marked `hidden: true` unintentionally.
  </Accordion>
  <Accordion title="How do I add a new section?">
    Add a top-level `- section:` entry to the relevant product's YAML file with a `contents:` list of pages. See [Sections, pages, and folders](/learn/docs/navigation) for the full schema.
  </Accordion>
  <Accordion title="How do I redirect an old URL?">
    Add a `redirects:` entry to `fern/docs.yml` mapping the old path to the new path. Redirects take effect on the next publish.
  </Accordion>
</AccordionGroup>

## Authoring conventions

A few patterns to keep in mind when adding or editing pages:

1. **Prefer updates over duplicates.** Search the repo before creating a new page; an existing page may already cover the topic.
2. **Lead with the user benefit.** Open each page with what the reader will be able to do, not how the feature is implemented.
3. **Cross-link generously.** When you mention a concept covered elsewhere, link to it using a `/learn/...` URL path.
4. **Keep examples runnable.** Snippets should be valid as written — readers will copy them.
5. **Match the surrounding style.** Mirror the heading depth, tone, and component choices of nearby pages.

## How to remove this page

Because this page is wired into the hidden **Resources** section, removing it takes two changes:

1. Delete `fern/products/docs/pages/resources/sample-test-page.mdx`.
2. Remove the matching `- page: Sample test page` entry from `fern/products/docs/docs.yml`.

No redirect is needed — the page is `noindex` and not linked from any customer-visible surface.
