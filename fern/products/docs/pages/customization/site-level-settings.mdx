The `docs.yml` file is your primary tool for customizing colors, typography, layout, analytics, and more across your documentation site. Start here for most customization needs before considering [custom CSS and JavaScript](/docs/customization/custom-css-js) for advanced use cases.

### YAML schema validation

To enable intelligent YAML validation and autocompletion in your editor, add this line at the top of your `docs.yml` file:

```yaml docs.yml
# yaml-language-server: $schema=https://schema.buildwithfern.dev/docs-yml.json
```

This enables real-time schema validation and autocompletion based on our [complete schema](https://github.com/fern-api/fern/blob/09555d587294fd3dc77ceb35f21e8976a5a2b7a2/fern/apis/docs-yml/definition/docs.yml#L110).

## Theme configuration

Customize the visual style of specific UI elements across your documentation site.

```yaml docs.yml
theme:
  sidebar: minimal
  body: canvas
  tabs: bubble
  page-actions: toolbar
  footer-nav: minimal
```

The `theme` configuration is not currently available as a Schema type. The available options are:

- `sidebar`: `default` shows the full sidebar with section headers and icons; `minimal` displays a cleaner, simplified sidebar without decorative elements.
- `body`: `default` uses a flat background; `canvas` adds a subtle card-like container around the content area.
- `tabs`: `default` uses underlined tabs; `bubble` displays tabs with rounded pill-shaped backgrounds.
- `page-actions`: `default` shows individual icon buttons; `toolbar` groups actions into a compact horizontal toolbar.
- `footer-nav`: `default` shows full previous/next cards with titles and descriptions; `minimal` displays simple text links.

## Settings configuration

```yaml docs.yml
settings:
  search-text: "Search the docs..."
  disable-search: false
  disable-explorer-proxy: false
  disable-analytics: true
  dark-mode-code: true
  default-search-filters: true
  http-snippets: false
  hide-404-page: true
  use-javascript-as-typescript: false
```

The `settings` configuration is not currently available as a Schema type. The available options are:

- `search-text`: The text to display in the searchbar. Defaults to "Search".
- `disable-search`: If set to true, the searchbar will be disabled.
- `disable-explorer-proxy`: If set to true, the API Explorer will bypass the proxy when sending requests directly to your API. Your API must have CORS enabled.
- `dark-mode-code`: If set to true, code blocks will be displayed in dark mode regardless of the selected theme.
- `default-search-filters`: If set to true, search will display results for pages within the current product and version.
- `http-snippets`: Controls the display of [HTTP snippets in the API Reference](/docs/api-references/http-snippets). Set to `false` to disable, or provide a list of languages.
- `hide-404-page`: If set to true, users will be redirected to the home page when navigating to a non-existent page.
- `use-javascript-as-typescript`: If set to true, TypeScript snippets will be displayed as JavaScript snippets.
- `disable-analytics`: If set to true, all analytics integrations will be disabled.

## Page actions configuration

Configure the page action buttons that appear throughout your documentation. By default, **Copy Page** (`copy-page`), **View as Markdown** (`view-as-markdown`), and **Ask AI** (`ask-ai`) are enabled. 

```yaml docs.yml
page-actions:
  default: copy-page
  options:
    copy-page: false
    ask-ai: false
    cursor: true
```

The `page-actions` configuration is not currently available as a Schema type. The available options are:

- `default`: The default page action to display. Options: `copy-page`, `view-as-markdown`, `ask-ai`, `chatgpt`, `claude`, `cursor`, `vscode`.
- `options.copy-page`: When enabled, displays a button to copy the entire page content.
- `options.view-as-markdown`: When enabled, displays a button to view the raw Markdown source.
- `options.ask-ai`: When enabled, displays an "Ask AI" button for AI-powered assistance.
- `options.chatgpt`: When enabled, displays an "Open in ChatGPT" button.
- `options.claude`: When enabled, displays an "Open in Claude" button.
- `options.cursor`: When enabled, displays an "Open in Cursor" button.
- `options.vscode`: When enabled, displays an "Open in VS Code" button.

## Dynamic snippets configuration

By default, SDK snippets are static code examples that are displayed in your API Reference. Alternatively, you can use dynamic SDK snippets that allow users to modify parameters and see code examples update in real time. 

Enable dynamic snippets in `docs.yml`, then configure them by [following the SDK snippets setup instructions](/docs/api-references/sdk-snippets). 

```yaml docs.yml
experimental:
  dynamic-snippets: true
```
