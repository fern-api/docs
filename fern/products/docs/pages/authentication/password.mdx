Password protection restricts access to your documentation site using a shared password. This is useful for pre-release documentation, internal resources, or any content you want to keep private without requiring individual user accounts.

Password protection is a standalone feature that doesn't involve SSO or any external identity provider.

## How it works

When password protection is enabled, visitors are redirected to a built-in login page where they must enter the password. The password is verified directly against the configured value, and once authenticated, users can browse the site until their session expires. No changes to `docs.yml` or your Fern config repository are required.

## Page-level access control

By default, all pages require the password when protection is enabled. You can optionally configure allowlist and denylist patterns to control which pages require the password:

- **Allowlist**: Regex patterns for pages that are publicly accessible without a password.
- **Denylist**: Regex patterns for pages that require the password. Takes precedence over the allowlist.

For example, you can make your getting started guides public while keeping API Reference pages behind the password.

## Setting up password protection

To enable password protection for your documentation site, [contact Fern](https://buildwithfern.com/contact) or reach out via Slack. Fern will configure the password for your site.

## Self-hosted deployments

For self-hosted documentation, password protection is configured via environment variables on the container instead. See [Self-hosted authentication](/learn/docs/self-hosted/authentication#password-authentication) for setup instructions.
