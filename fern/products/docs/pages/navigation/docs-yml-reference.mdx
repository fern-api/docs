## docs.yml Overview
The `docs.yml` file controls the structure and navigation of your documentation site. It allows you to organize your content into sections and specify how they are displayed.

## File Structure
Place the `docs.yml` file in your documentation's root directory. The file uses YAML syntax to define the navigation structure.

## Configuration Options

### Basic Section
A basic section requires a title and path to the content:

```yaml
- section: Getting Started
  path: ./pages/getting-started.md
```

### Section with Subsections
Nest content using the `contents` property:

```yaml
- section: API Reference
  path: ./pages/api/overview.md
  contents:
    - page: Authentication
      path: ./pages/api/auth.md
    - page: Endpoints
      path: ./pages/api/endpoints.md
```

### Section Display Options
Control how sections appear using these properties:

<ParamField query="collapsed" type="boolean">
  When `true`, the section will appear collapsed and bold like a section header. Useful for standalone pages that should have section-like styling.
</ParamField>

<ParamField query="path" type="string">
  Path to the content file for this section.
</ParamField>

<ParamField query="contents" type="array">
  Array of subsections and pages. Use empty array `[]` if no subsections are needed.
</ParamField>

### Example: Section with Bold Styling
To make a standalone page appear as a bold section header:

```yaml
- section: Overview
  collapsed: true
  path: ./pages/overview.md
  contents: []
```

### Full Example
Here's a complete example showing various configuration options:

```yaml
- section: Getting Started
  path: ./pages/getting-started.md
  contents:
    - page: Quick Start
      path: ./pages/quickstart.md
    - page: Installation
      path: ./pages/install.md

- section: Overview
  collapsed: true
  path: ./pages/overview.md
  contents: []

- section: API Reference
  path: ./pages/api/overview.md
  contents:
    - page: Authentication
      path: ./pages/api/auth.md
    - page: Endpoints
      path: ./pages/api/endpoints.md
```

## Best Practices
- Use clear, descriptive section names
- Organize content logically with related items grouped together
- Keep navigation structure shallow when possible (avoid deep nesting)
- Use the `collapsed` property for standalone pages that should appear as section headers
