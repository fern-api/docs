Each product can contain its own distinct versions, tabs, sections, pages, and API references. Products can share content as well. 

## Add Products to Your Docs

<Steps toc={true}>
<Step title="Define your products">

Create a `products` folder inside of your `fern` folder. To specify a product's contents and navigational structure, add a `.yml` file to the `products` folder for each product.
Make sure to include the `navigation` and `tabs` properties, if applicable.

```bash {4, 7-8}
fern/
  ├─ fern.config.json
  ├─ generators.yml
  ├─ docs.yml # Site-level contents and navigation
  └─ products/
    ├─ ...
    ├─ product-a.yml # Contents and navigation for Product A
    └─ product-b.yml # Contents and navigation for Product B
```

<CodeBlocks>
<CodeBlock title="products/product-a.yml">
```yaml
navigation: 
  - section: Introduction
    contents:
      - page: Shared Resource
        path: ../pages/shared-resource.mdx
  - api: API Reference
```
</CodeBlock>
<CodeBlock title="products/product-b.yml">
```yaml
tabs: 
  api: 
    title: API Reference
    icon: puzzle
  help:
    title: Help Center
    icon: home
    
 navigation:
  - tab: api
     contents:
        - section: Introduction
           contents: 
              - page: My Page
                path: ./latest/pages/my-page.mdx # relative path to the file
              - page: Shared Resource
                path: ../pages/shared-resource.mdx
        - api: API Reference
   - tab: help
      contents: 
         - section: Help Center
           contents: 
              - page: Contact Us
                 path: contact-us.mdx
```
</CodeBlock>
</CodeBlocks>
</Step>
<Step title="Add your product configuration">

To define a product, add an item to the `products` list in `docs.yml`, specifying the `display-name` and `path`.

The optional parameters are: `image`, `icon`, `subtitle`, `slug`, and `versions`.

<Note>If you provide both an `image` and an `icon`, the `image` will take precedence.</Note>

The below example shows a `docs.yml` configuration for a site with one unversioned product and one versioned product:

<CodeBlock title="docs.yml">
```yaml
products:
  - display-name: Data API
    path: ./products/data/versions/v2.yml
    subtitle: Integrate with your data
    icon: fa-light fa-database
    image: ./assets/product-selector/data-api-image.svg
    slug: data
    versions:
      - display-name: v2
        slug: v2.0.0
        path: ./products/data/versions/v2.yml
      - display-name: v2 (beta)
        slug: v2.0.0-beta
        path: ./products/data/versions/v2-beta.yml
      - display-name: v1 (legacy)
        slug: v1.0.0
        path: ./products/data/versions/v1.yml

  - display-name: Payments API
    path: ./products/payments.yml
    subtitle: Process payments
    icon: fa-light fa-credit-card
    slug: payments
```
</CodeBlock>
</Step>
<Step title="Add versioning to your products (optional)">

You can add versions to your products using the `versions` field in your product configuration. A product can have multiple versions, each with its own configuration file and content.

Here's an example file structure for a versioned product:

<CodeBlock>
```bash
fern/
  ├─ products/
  │  └─ data/
  │     └─ versions/
  │        ├─ v2.yml
  │        ├─ v2-beta.yml
  │        └─ v1.yml
  └─ docs.yml
```
</CodeBlock>

To configure versions for a product:

1. Create a `versions` directory in your product folder
2. Add a YAML file for each version
3. Configure the versions in your `docs.yml` file:

<CodeBlock title="docs.yml">
```yaml
products:
  - display-name: Data API
    path: ./products/data/versions/v2.yml # Default version
    subtitle: Integrate with your data
    icon: fa-light fa-database
    slug: data
    versions:
      - display-name: v2 # Current version
        slug: v2.0.0
        path: ./products/data/versions/v2.yml
      - display-name: v2 (beta) # Beta version
        slug: v2.0.0-beta
        path: ./products/data/versions/v2-beta.yml
      - display-name: v1 (legacy) # Legacy version
        slug: v1.0.0
        path: ./products/data/versions/v1.yml
```
</CodeBlock>

The `path` at the product level determines which version is shown by default. Each version needs:
- `display-name`: The name shown in the version selector
- `slug`: A unique identifier for the version
- `path`: Path to the version's YAML configuration file

<Note>Products can be a mix of versioned and unversioned. Simply omit the `versions` field for products that don't need versioning.</Note>

For more details on versioning, see our [versioning docs](/docs/navigation/versions).
</Step>
<Step title="Remove extra navigation from docs.yml">

If your `docs.yml` file includes a `navigation` field or a `tabs` field, be sure to remove them. Those fields should now belong in the product-specific `.yml` files. 
</Step>
</Steps>

## Customizing Selector Styling

You can directly customize the appearance of the product and version selectors by targeting their CSS classes:

- `fern-product-selector` - Controls the styling of the product selector
- `fern-version-selector` - Controls the styling of the version selector

<Frame>
  <img src="webflow-dropdown-selector.avif" alt="Example of a styled product selector" />
</Frame>

### Common Styling Adjustments

**Adjusting positioning:**
Use `transform: translateY(Npx)` to adjust the vertical positioning of the selectors. This ensures that the product and version selectors match the line height of your logo for better visual alignment.

**Enhancing visual prominence:**
You can modify the border radius and add borders to make the selectors more prominent and better integrated with your site's design aesthetic.

```css
.fern-product-selector {
  transform: translateY(2px);
  border-radius: 8px;
  border: 1px solid var(--border);
}

.fern-version-selector {
  transform: translateY(1px);
  border-radius: 1000px;
  border: 1px solid var(--border);
}
```

## Customizing Dropdown Styling

The dropdown menus for product and version selectors can be customized using these specific CSS classes:

- `fern-product-selector-radio-group` - Controls the styling of the product dropdown
- `fern-version-selector-radio-group` - Controls the styling of the version dropdown
