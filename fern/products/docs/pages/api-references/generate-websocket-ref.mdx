Fern generates WebSocket API Reference documentation from your AsyncAPI specification or [Fern Definition](/learn/api-definition/fern/websockets). The AsyncAPI specification describes message-driven APIs in a machine-readable format. Fern supports the [v2](https://www.asyncapi.com/docs/reference/specification/v2.x) and [v3](https://www.asyncapi.com/docs/reference/specification/v3.0.0) specifications.

## Configuration

### AsyncAPI

To configure WebSocket documentation using AsyncAPI:

1. Add your AsyncAPI specification file (e.g., `asyncapi.yml`) to your `/fern` directory
2. Configure your `generators.yml`

<CodeBlock title='generators.yml'>
  ```yaml
api:
    path: asyncapi.yml
    origin: https://github.com/your-org/your-repo/blob/main/asyncapi.yml
  ```
</CodeBlock>

<ParamField path="path" required>
    Location of your AsyncAPI specification file
</ParamField>

<ParamField path="origin">
    URL where the specification file is hosted if you want Fern to fetch it from a remote location
</ParamField>

### Fern Definition

To configure WebSocket documentation using a Fern Definition, create a separate YAML file for your WebSocket channel. Each WebSocket is defined by a `channel` object.

<CodeBlock title='realtime.yml'>
  ```yaml
channel:
  path: /v1/realtime/conversations
  auth: false
  messages:
    Config:
      origin: client
      body: ConfigMessage
    UserAudio:
      origin: client
      body: UserAudioChunk
    ServerResponse:
      origin: server
      body: ServerMessage
  ```
</CodeBlock>

You can define multiple WebSockets in the same file or use separate files for each WebSocket. For more details on the WebSocket schema, see [WebSockets in the Fern Definition](/learn/api-definition/fern/websockets).

## Adding WebSockets to navigation

To display your WebSocket in the docs sidebar, reference it in your `docs.yml` navigation using the `WSS` prefix followed by the WebSocket path.

<CodeBlock title='docs.yml'>
  ```yaml
navigation:
  - section: API Reference
    contents:
      - api: API Reference
        layout:
          - endpoint: WSS /v1/realtime/conversations
            title: Realtime Conversations
  ```
</CodeBlock>

You can customize the WebSocket endpoint display with `title` and `slug` properties, similar to REST endpoints. For more details on customizing the API Reference layout, see [Customize API Reference layout](/learn/docs/api-references/customize-api-ref).

## Common use cases

WebSockets enable real-time, bidirectional communication, making them essential for:

- **FinTech**: Market data streams, trading updates, live pricing
- **Voice AI**: Live transcription, real-time voice processing
- **Gaming**: Multiplayer interactions, live state updates
- **Communications**: Chat applications, collaboration tools
