Fern generates WebSocket API Reference documentation from your AsyncAPI specification or [Fern Definition](/learn/api-definition/fern/websockets). The AsyncAPI specification describes message-driven APIs in a machine-readable format. Fern supports the [v2](https://www.asyncapi.com/docs/reference/specification/v2.x) and [v3](https://www.asyncapi.com/docs/reference/specification/v3.0.0) specifications.

## AsyncAPI

<Steps>
<Step title="Add your AsyncAPI specification">
Add your AsyncAPI specification file (e.g., `asyncapi.yml`) to your `/fern` directory.
</Step>

<Step title="Configure generators.yml">
Reference your AsyncAPI file in `generators.yml`:

<CodeBlock title='generators.yml'>
```yaml
api:
  path: asyncapi.yml
```
</CodeBlock>

<ParamField path="path" required>
Location of your AsyncAPI specification file
</ParamField>

<ParamField path="origin">
URL where the specification file is hosted if you want Fern to fetch it from a remote location
</ParamField>
</Step>

<Step title="Add to navigation">
Reference your WebSocket in `docs.yml` using the `WSS` prefix followed by the WebSocket path:

<CodeBlock title='docs.yml'>
```yaml
navigation:
  - api: API Reference
    layout:
      - endpoint: WSS /v1/realtime/conversations
        title: Realtime Conversations
```
</CodeBlock>
</Step>
</Steps>

## Fern Definition

<Steps>
<Step title="Create a WebSocket definition file">
Create a YAML file for your WebSocket channel (e.g., `realtime.yml`) and define your WebSocket using the `channel` object. For the full schema and examples, see [WebSockets in the Fern Definition](/learn/api-definition/fern/websockets).

Fern auto-discovers WebSocket definition files, so no `generators.yml` configuration is required.
</Step>

<Step title="Add to navigation">
Reference your WebSocket in `docs.yml` using the `WSS` prefix followed by the WebSocket path:

<CodeBlock title='docs.yml'>
```yaml
navigation:
  - api: API Reference
    layout:
      - endpoint: WSS /v1/realtime/conversations
        title: Realtime Conversations
```
</CodeBlock>
</Step>
</Steps>

You can customize the WebSocket endpoint display with `title` and `slug` properties, similar to REST endpoints. For more details, see [Customize API Reference layout](/learn/docs/api-references/customize-api-ref).

## Common use cases

WebSockets enable real-time, bidirectional communication, making them essential for:

- **FinTech**: Market data streams, trading updates, live pricing
- **Voice AI**: Live transcription, real-time voice processing
- **Gaming**: Multiplayer interactions, live state updates
- **Communications**: Chat applications, collaboration tools
