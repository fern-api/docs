title: Display SDK snippets

---


If you use Fern to generate SDKs, you can display SDK code snippets in your API Reference. These snippets show examples using your actual SDK in TypeScript, Python, Go, and other supported languages.

Once configured, SDK snippets replace [HTTP snippets](/learn/docs/api-references/http-snippets).

<Note title="Dynamic snippets">
  By default, SDK snippets are dynamic code examples that allow users to modify parameters and see code examples update in real time across all supported languages. 
  
  Alternatively, you can [disable dynamic snippets in your `docs.yml`](/learn/docs/configuration/site-level-settings#experimentaldynamic-snippets) and use static code examples.
</Note>

## Configuration

To configure SDK snippets, first name your SDKs in `generators.yml` and then reference that name in `docs.yml`. If you generate SDKs with `sdk-config.yml`, [enable snippets in `sdk-config.yml`](#use-sdk-snippets-with-sdk-configyml) instead.

<Steps>

### Add examples to your API definition

Fern needs to read request examples from your API definition to generate code snippets. For OpenAPI, follow [Swagger's examples documentation](https://swagger.io/docs/specification/adding-examples/).

### Define a package name for your SDK(s)

Configure package names in your `generators.yml` file:
*  For **Python, TypeScript, Ruby, and .NET/C#**, add `package-name: your-package-name` to the `output` section.
*  For **Java**, add `coordinate: com.your-org:your-package-name` to the `output` section.
*  For **PHP**, add `packageName: YourPackageName` to the `config` section.
*  For **Go**, add `repository: your-organization/your-repository` to the `github` section.
*  For a [Fern-generated CLI](/learn/cli-generator/get-started/overview), add `package-name: your-package-name` to the `output` section of the `fern-cli-generator`. Snippets show commands that start with the CLI's `binaryName`.

<Note>Fern supports SDK snippets for TypeScript, Python, Ruby, Go, Java, PHP, .NET/C#, and Fern-generated CLIs. [File an issue](https://github.com/fern-api/fern/issues) to request additional languages.</Note>

<CodeBlock title="generators.yml">
```yaml {9, 16, 22, 28, 34, 41, 46, 52}
groups:
  production:
    generators:
      - name: fern-python-sdk
        version: <Markdown src="/snippets/version-number-python.mdx" />
        output:
          location: pypi
          token: ${PYPI_TOKEN}
          package-name: your-package-name # <--- add this field
        ...
      - name: fern-typescript-sdk
        version: <Markdown src="/snippets/version-number-ts.mdx" />
        output:
          location: npm
          token: ${NPM_TOKEN}
          package-name: your-package-name # <--- add this field
      - name: fern-ruby-sdk
        version: <Markdown src="/snippets/version-number-ruby.mdx" />
        output:
          location: rubygems
          token: ${RUBYGEMS_TOKEN}
          package-name: your-package-name # <--- add this field
      - name: fern-csharp-sdk
        version: <Markdown src="/snippets/version-number-csharp.mdx" />
        output:
          location: nuget
          api-key: ${NUGET_API_KEY}
          package-name: your-package-name # <--- add this field
        ...
      - name: fern-java-sdk
        version: <Markdown src="/snippets/version-number-java.mdx" />
        output:
          location: maven
          coordinate: com.your-org:your-package-name # <--- add this field
        ...
      - name: fern-php-sdk
        version: <Markdown src="/snippets/version-number-php.mdx" />
        github:
          repository: your-organization/your-repository
        config:
          packageName: YourPackageName # <--- add this field
        ...
      - name: fern-go-sdk
        version: <Markdown src="/snippets/version-number-go.mdx" />
        github:
          repository: your-organization/your-repository # <--- add this field
        ...     
      - name: fern-cli-generator
        version: <Markdown src="/snippets/version-number-cli-generator.mdx" />
        output:
          location: npm
          package-name: your-package-name # <--- add this field
        config:
          binaryName: your-cli
        ...
```
</CodeBlock>

### Add the package name to your docs configuration

Add the package name for the corresponding SDK to your `docs.yml` file:
  *  **For Python, TypeScript, Ruby, and .NET/C#**, `your-package-name` must match the `your-package-name` that you configured in your `generators.yml` file.
  *  **For Java**, `com.your-org:your-package-name` must match the `coordinate` that you configured in your `generators.yml` file.
  *  **For PHP**, `YourPackageName` must match the `packageName` that you configured in your `generators.yml` file.
  *  **For Go**, use the exact URL where the SDK repository is located, including the `https://github.com/`. 
  *  **For a CLI**, `your-package-name` must match the `package-name` in the `output` section of the `fern-cli-generator`. If the CLI generator has no package name (for example, it outputs to a local directory) and is the only CLI generator in the API's `generators.yml`, Fern uses it for any `cli` value.

<CodeBlock title="docs.yml">
```yaml {3-11}
navigation:
  - api: API Reference
    snippets:
      python: your-package-name  # <--- needs to match the naming in generators.yml
      typescript: your-package-name # <--- needs to match the naming in generators.yml
      ruby: your-package-name # <--- needs to match the naming in generators.yml
      csharp: your-package-name # <--- needs to match the naming in generators.yml
      java: com.your-org:your-package-name # <--- needs to match the coordinate in generators.yml
      php: YourPackageName # <--- needs to match the packageName in generators.yml
      go: https://github.com/your-organization/your-repository # <--- needs the https://github.com/ prefix
      cli: your-package-name # <--- needs to match the package-name in generators.yml
```
</CodeBlock>

<Note>
  To display different package names for SDK users versus documentation users, [use overrides files](/learn/api-definitions/asyncapi/overrides#separate-overrides-for-sdks-and-docs).
</Note>

### Trigger generation

Trigger your docs generation by running `fern generate --docs` locally or in CI/CD (i.e., GitHub Actions). The SDK snippets appear in a dropdown.

</Steps>

## Use SDK snippets with `sdk-config.yml`

When you generate SDKs with [`sdk-config.yml`](/learn/sdks/reference/sdk-config), SDK generation saves a snippets file with each build. `fern generate --docs` reads that file and adds the snippets to your API Reference endpoints. This works for TypeScript, Python, Java, Go, Ruby, C#, and PHP SDKs.

<Steps>

### Enable snippets in `sdk-config.yml`

Set `docs.snippets.enabled` to `true` at the top level, where every target inherits it, or in a single target's `docs` block. Fern finds each SDK's build by its `sdkName`, so the target needs an `sdkName` of its own or the top-level one.

<CodeBlock title="sdk-config.yml">
```yaml {1, 3-5}
sdkName: plant-store
docs:
  snippets:
    enabled: true
targets:
  - language: python
  - language: typescript
```
</CodeBlock>

### Add the SDK version to `docs.yml`

Under your `api:` entry, add a `snippets` entry for each language you build, with the version you're about to build. List only the languages you build.

<CodeBlock title="docs.yml">
```yaml {3-9}
navigation:
  - api: API Reference
    snippets:
      python:
        package: your-package-name
        version: 1.2.0
      typescript:
        package: your-package-name
        version: 1.2.0
```
</CodeBlock>

### Build the SDKs at that version

Run `fern generate` to build the SDKs with a new [version](/learn/sdks/reference/sdk-config#sdkversion) that matches the `version` in `docs.yml`. Fern reads snippets only from a successful build made with snippets enabled, and uses the newest such build of each language with a matching `sdkName` and version.

### Trigger generation

Run `fern generate --docs`. The output includes a line such as `Loaded SDK snippets (python: 12, typescript: 12)` with the number of endpoint snippets read for each language, and the snippets appear in the language dropdown on each endpoint. A [code sample you wrote](/learn/api-definitions/openapi/extensions/request-response-examples#code-samples) for an endpoint in the same language takes precedence over the generated snippet.

If Fern can't find or read the snippets for a language, the CLI logs a warning and publishes the docs without them.

</Steps>

## Additional options

### Specify SDK versions

You can specify which SDK version to use when generating code snippets.

<CodeBlock title="docs.yml">
```yaml {4-6}
navigation:
  - api: API Reference
    snippets:
      python:
        package: your-package-name  # <--- needs to match the naming in generators.yml
        version: your-version number # SDK version to use for snippets
```
</CodeBlock>

### Set default snippet language

Use the `default-language` key at the top indentation level of `docs.yml`. This setting applies to both SDK snippets and HTTP snippets.

<CodeBlock title="docs.yml">
```yaml {1}
default-language: typescript

navigation:
  - api: API Reference
    snippets:
      python: your-package-name
      typescript: your-package-name
```
</CodeBlock>
