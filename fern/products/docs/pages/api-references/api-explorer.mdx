## Authentication

The API Explorer supports [all authentication schemes](/learn/api-definitions/openapi/authentication) configured in your OpenAPI spec or in `generators.yml`, including multiple authentication schemes. When multiple schemes are available, the API Explorer automatically displays them in a dropdown menu, allowing users to select and configure their preferred authentication method before sending requests.

Once a user sets their authentication credentials, their credentials persist throughout their entire exploration session.

<Info>
Authentication credentials are only stored client-side using cookies. No sensitive user information is collected or stored.
</Info>

To automatically populate API keys for logged-in users, see [API key injection](/learn/docs/authentication/features/api-key-injection).

### OAuth client credentials

When an endpoint uses [OAuth client credentials](/learn/api-definitions/openapi/authentication#oauth-client-credentials) authentication, the API Explorer presents two input modes:

- **Credentials** — Fill in the token endpoint's request fields (e.g., `client_id` and `client_secret`) and click **Fetch Bearer Token**. The API Explorer calls your token endpoint through a server-side proxy and extracts the `access_token` from the response using the JSONPath defined in your `response-properties`. The token is then attached to all subsequent requests.
- **Bearer Token** — Paste an existing access token directly, bypassing the token exchange.

The field names shown in the Credentials form match the `request-properties` mapping in your OAuth auth scheme configuration. For example, if your token endpoint expects `username` and `password` instead of `client_id` and `client_secret`, configure `request-properties` accordingly and the form fields update to match.

After a successful token fetch, the **Generated OAuth Token** field displays the retrieved token. Click **Refresh Bearer Token** to re-fetch if the token expires. The token is sent using the header and prefix defined by `token-header` (default `Authorization`) and `token-prefix` (default `Bearer`).

<Note>
If the token endpoint returns a non-200 response or a non-JSON body, the API Explorer displays a "Failed to login" error. Verify your token endpoint URL and `request-properties` configuration. When your token endpoint is hosted at a different domain than your API, configure [multi-URL environments](/learn/api-definitions/ferndef/api-yml/environments#multiple-urls-per-environment) to set the correct base URL for the token request.
</Note>

## Multiple environments

When multiple server URLs are configured in [OpenAPI](/learn/api-definitions/openapi/extensions/server-names-and-url-templating), users can switch between environments (e.g., production and sandbox) from a dropdown in the API Explorer. The selected environment persists as they navigate between pages.

<div style="position: relative; padding-bottom: 50.63657407407407%; height: 0;"><iframe src="https://www.loom.com/embed/cb642161678e41cabcb677b900006f40?sid=5e45243c-3ba1-45cf-860b-72eee1970fc5?hide_owner=true&hide_share=true&hide_title=true&hideEmbedTopBar=true" frameborder="0" webkitallowfullscreen mozallowfullscreen allowfullscreen style="position: absolute; top: 0; left: 0; width: 100%; height: 100%;"></iframe></div>

Users can also double-click the server URL to manually edit it, allowing for quick testing against custom environments or endpoints.


Here's an example of the [Flagright docs site](https://docs.flagright.com/framl-api/api-reference/api-reference/transactions/get) with multiple server names configured.

<CodeBlock>
```yaml
openapi: 3.0.0
servers:
  - url: https://sandbox.api.flagright.com
    x-fern-server-name: Sandbox API server (eu-1)
  - url: https://sandbox-asia-1.api.flagright.com
    x-fern-server-name: Sandbox API server (asia-1)
```
</CodeBlock>

## Control API Explorer availability

For OpenAPI specs, the API Explorer is enabled by default for all endpoints. You can disable it globally or per endpoint using the [`x-fern-explorer`](/learn/api-definitions/openapi/extensions/api-explorer-control) extension. This is commonly used to disable the Explorer for destructive operations, payment processing, or admin-only endpoints.
