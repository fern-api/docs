Audiences are a useful tool for segmenting your API for different consumers. Common examples of audiences include `public` 
and `beta`. You can configure audiences in [the OpenAPI Specification](/learn/api-definitions/openapi/extensions/audiences).

Once you've added audiences to your API Specification, you can filter to that audience by adding the `audience` property to the `api` object in your `docs.yml` navigation.

<CodeBlocks>
```yaml title="docs.yml" {3-4}
navigation:
  - api: API Reference
    audiences:
      - public
```
</CodeBlocks>

Here's [an example from Schematic](https://github.com/SchematicHQ/schematic-fern-config/blob/e19f5ea69a343727ed018e79127bf4fd20ad0f7b/fern/docs.yml#L128-L129) in production.

## Hide a single field from your API Reference

To hide one property, for example an `internalNotes` field on a `Plant` response, tag it with [`x-fern-audiences`](/learn/api-definitions/openapi/extensions/audiences) and leave that audience out of the `audiences` filter shown above. The field also segments across your SDKs, which are filtered separately in `generators.yml`.

```yaml title="openapi.yml" {7-8}
components:
  schemas:
    Plant:
      properties:
        internalNotes:
          type: string
          x-fern-audiences:
            - internal
```

To remove the field from your docs entirely while keeping it in your SDKs, delete it from the docs spec with an [OpenAPI overlay](/learn/api-definitions/openapi/overlays). To drop it from every Fern output, including docs, SDKs, and the CLI, mark it with [`x-fern-ignore`](/learn/api-definitions/openapi/extensions/ignoring-elements).

`x-fern-availability` does not hide a field. It only renders an [availability badge](/learn/api-definitions/openapi/extensions/availability) (Alpha, Beta, Deprecated, and so on) next to the property.

## Instance audiences

API Reference audiences work alongside [instance audiences](/docs/configuration/products#add-instance-audiences), which control which products and versions appear in each documentation instance. You can use both features together:

- **API Reference audiences** - Control which endpoints and schemas appear within API References
- **Instance audiences** - Control which products and versions appear in each instance

For example, you might have a `public` API Reference that shows only public endpoints. To ensure this API Reference only appears on your public documentation site, tag the containing product or version with the `public` audience.
