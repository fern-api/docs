Fern Agent edits your documentation and analyzes your organization's Fern data. It's an expert in Fern configuration — `docs.yml`, components, versioning, redirects, and access control.

## Setup

Open the [Fern Dashboard](https://dashboard.buildwithfern.com/) and start a conversation in the chat panel. From the chat panel:

- **Slack** — click **Connect Slack**, select the workspace, and add Fern to the channels where your team discusses docs. Requires Slack admin access.
- **Coding agent** — click **Onboard your agent** to register [Fern's MCP server](/learn/docs/ai-features/fern-mcp-servers).

To connect Slack manually, use your [Fern API key](/learn/dashboard/configuration/api-keys) and the `organization` field from `fern/fern.config.json`:

```bash
curl -X POST https://fai.buildwithfern.com/slack/agent/install \
  -H "Authorization: Bearer <FERN_TOKEN>" -H "Content-Type: application/json" \
  -d '{"org_id":"<org>"}'
```

Onboard your agent by handing it this prompt:

<Prompt title="Set up Fern Agent in your terminal">
Fetch and execute the appropriate instructions to set me up for Fern from https://buildwithfern.com/learn/docs/ai-features/agent-setup.md
</Prompt>

## Making requests in Slack

Tag `@Fern` in a channel where it has been added. Fern only responds when directly tagged.

- Describe the change or analysis you need; Fern replies and opens PRs as needed.
- Attach images or files for additional context.
- When tagged in a thread, Fern reads the full conversation before responding.
- Iterate by replying in the thread; merge the PR like any other when it's ready.
- Click the Dashboard link in any reply to continue the session there.

<Note title="Fern Agent vs. Fern Writer">
Fern Agent is an expansion of Fern Writer. Existing Fern Writer installations keep working — the request flow is unchanged. Fern Agent adds organization context (traffic, reader questions, deployments, site config) and extends the same capabilities to the Fern Dashboard and coding agents over MCP.
</Note>

## Automations

Create an automation on the **Automations** page of the [Fern Dashboard](https://dashboard.buildwithfern.com/), or describe the recurring work in the chat panel or @Fern in Slack and Fern Agent sets it up for you.

- Each run starts a fresh conversation from the prompt and works in a single turn.
- Runs report back on what they did, found, or skipped.
- A run only changes the docs when the prompt explicitly requests it.

### Setup

<Steps>
<Step title="Write the prompt">
Open **Automations**, select **New automation** (pick a **Blank automation** or one of Fern's templates), and describe what each run should produce. Prompts hold up to 2,000 characters.
</Step>

<Step title="Set the schedule">
Choose daily or a day of the week, a time of day, and timezone. A schedule fires at most once every 20 hours.
</Step>

<Step title="Check what a run produces">
**Save** your new automation, then select **Run now** to test the prompt. Manual runs don't affect the next scheduled run. Runs take a few minutes; finished runs are reported via email or Slack when you [connect Fern Agent to Slack](#setup).
</Step>
</Steps>

- Every member of your organization can see automations; only the creator can edit, delete, or run one.
- Turning an automation off preserves its prompt and history; deleting it discards both (PRs it opened are unaffected).
- Run history covers the last 30 days.

## Privacy and data handling

- Fern Agent acts with your own Fern permissions — it reads and edits only what your account can already see.
- Requests are scoped to a single session; prompts, Slack messages, and attachments are stored only to complete the task and aren't retained afterward.
- Editing is powered by [Devin from Cognition](https://cognition.ai/blog/introducing-devin).
- Neither Fern nor [Devin](https://docs.devin.ai/admin/security#how-is-your-data-used-to-improve-devin) uses your data to train AI models — Fern opts out of Devin's data collection for model training.
