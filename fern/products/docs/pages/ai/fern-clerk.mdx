Fern Clerk is an AI agent that writes and maintains documentation from your code. It works in two ways, and both deliver pull requests, so nothing changes your docs until you merge.

| If you | Fern Clerk will |
|--------|-----------------|
| Have code but no docs | [Write a first version of your docs](#write-docs-from-your-code) from a repository |
| Have a docs site | [Keep your docs in sync](#keep-docs-in-sync-with-your-code) by reviewing your pull requests and proposing docs changes |

The two work together. After Fern Clerk writes a first version, the same automation keeps it current as your code changes.

Both start from the **Automations** page of the [Fern Dashboard](https://dashboard.buildwithfern.com/).

## Write docs from your code

Fern Clerk reads a repository, plans a docs site, writes the pages, checks that the site builds, and opens a pull request. It writes an API reference from the API specs it finds in the repository, and guides from the code.

<Steps>
<Step title="Pick the repository">
On the **Automations** page, select **Set up Fern Clerk**, then **Generate docs from your code**. Choose the repository to document and where the docs pull request opens: the same repository, in its `fern/` folder, or a separate one. Fern checks that your GitHub account can read the first repository and write to the second.
</Step>

<Step title="Add your brand and style (optional)">
Enter your website to have Fern pull colors and a logo from it. Add tone and style guidance, such as voice, audience, and terminology. Fern follows it while writing and saves it as `fern/AGENTS.md` in the docs repository, so later changes use the same voice.
</Step>

<Step title="Review the pull request">
The pull request describes the site's plan and what the run left out. Claims Fern couldn't trace to your code are marked `(needs confirmation)` on the page, and the pull request lists how many. Check those before you merge.
</Step>

<Step title="Merge to publish">
The pull request adds up to three workflow files (check, preview, and publish), skipping any the repository already has, and a `FERN_TOKEN` secret if it doesn't have one. Merging it publishes the site.
</Step>
</Steps>

Each repository can have one run in progress at a time. A repository can start 3 runs a day and an organization 10. If a run fails with a retryable error, select **Retry** on the run.

## Keep docs in sync with your code

Fern Clerk reviews each pull request in the repositories you connect, decides whether the docs need to change, and opens a docs pull request when they do. It opens that pull request in the repository your docs site publishes from.

You control:

- **When a pull request is reviewed**: after it merges, or while it's still open. See [Review trigger](/learn/docs/ai-features/fern-agent#review-trigger).
- **What happens when docs need to change**: open a pull request, or only record what would change and post nothing to GitHub. See [Observe only](/learn/docs/ai-features/fern-agent#observe-only).
- **How changes are grouped**: a docs pull request after each merge, or one daily or weekly digest. See [Grouping](/learn/docs/ai-features/fern-agent#grouping).
- **Which paths to ignore**: source paths whose changes never need docs. See [Ignored paths](/learn/docs/ai-features/fern-agent#ignored-paths).

Each reviewed pull request shows its decision and the docs pull request it produced. Mark a decision right or wrong with the thumbs up and thumbs down buttons. To see how it judges your changes before the next merge, select **Review recent merges** on the automation's page. It reviews your last 10 merged pull requests and posts nothing to GitHub.

Setup steps and settings are in the [Fern Clerk section of Fern Agent](/learn/docs/ai-features/fern-agent#fern-clerk).

## Permissions and data

Fern Clerk needs the Fern GitHub App installed on the repositories it reads and on the repository your docs publish from. It acts as the person who set it up, so it sees and changes only what that person can. If their GitHub authorization stops working, the automation shows **Reconnect needed** and pauses.

Fern Clerk redacts secrets from pull request content before reviewing it, skips credential files, and scans its docs edits for secrets before committing them.
