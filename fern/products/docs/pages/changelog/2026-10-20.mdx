## Role-based access control in local preview

<ChangelogTags>security, developer-tools</ChangelogTags>

`fern docs dev` now applies role-based access control the same way a preview link does. Use the role selector to view the site as a specific viewer and check which pages and navigation items each role sees. Password protection also works locally when you set `FERN_AUTH_TYPE=password` and `FERN_AUTH_SECRET` before starting the server.

## Analytics consent

<ChangelogTags>integrations, docs.yml</ChangelogTags>

You can now keep PostHog analytics off until a visitor consents. Set `settings.require-analytics-consent: true` in `docs.yml`, then report consent from your consent manager's callback (for example, Ketch or OneTrust) by setting `window.fernAnalyticsConsent` and dispatching a `fern-analytics-consent` event. Until consent is granted, Fern's built-in PostHog analytics and your own PostHog instance load no scripts, set no cookies, and send no events. Revoking consent turns PostHog off and removes its cookies and storage keys.
