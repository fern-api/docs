Fern automatically generates SEO essentials for your documentation site, including sitemaps, canonical URLs, meta tags, and `robots.txt`. Most sites work well out of the box, but you can customize settings to improve search visibility and control how your content appears in search results.

## What Fern generates automatically

Every Fern documentation site includes these SEO features without any configuration:

**Sitemap and robots.txt** are generated at `your-docs-url/sitemap.xml` and `your-docs-url/robots.txt`. Submit your sitemap to [Google Search Console](https://search.google.com/search-console) and [Bing Webmaster Tools](https://www.bing.com/webmasters) to help search engines discover your pages.

**Canonical URLs** are set automatically for each page. For versioned documentation, Fern uses the unversioned URL as the canonical to avoid duplicate content issues. You can [override canonical URLs](#canonical-urls-for-versioned-content) in frontmatter when needed.

**Meta tags** including `<title>`, meta description, and Open Graph tags are generated from your page's `title` and `description` fields. Fern also creates Twitter Card tags and JSON-LD structured data.

**LLM-optimized content** via `/llms.txt` and `/llms-full.txt` endpoints makes your documentation accessible to AI tools like Cursor, ChatGPT, and Claude. See [llms.txt](/learn/docs/ai-features/llms-txt) for details.

## SEO optimization checklist

Follow these steps to optimize your documentation for search engines:

<Steps>
### Add meta descriptions to key pages

Set a `description` in frontmatter for your most important pages. Keep descriptions between 150-160 characters. For API Reference pages, add descriptions to your OpenAPI spec's endpoint `description` fields.

```mdx title="getting-started.mdx"
---
title: Getting started
description: Learn how to integrate the PlantStore API in under 5 minutes. Includes authentication setup and your first API call.
---
```

### Configure site-wide metadata

Set default Open Graph and Twitter metadata in `docs.yml` so all pages have consistent branding when shared on social media.

```yaml title="docs.yml"
metadata:
  og:site_name: "PlantStore Documentation"
  og:image: "https://cdn.plantstore.dev/docs-social-card.png"
  twitter:site: "@PlantStoreAPI"
```

<Note>
Open Graph images must be hosted on a public URL (CDN, S3, or similar). Local file paths aren't supported.
</Note>

### Set up redirects for moved content

When you rename or move pages, add redirects to preserve SEO value and avoid broken links. See [redirects](/learn/docs/seo/redirects) for configuration details.

```yaml title="docs.yml"
redirects:
  - source: "/old-page"
    destination: "/new-page"
```

### Submit your sitemap

Submit `your-docs-url/sitemap.xml` to Google Search Console and Bing Webmaster Tools. This helps search engines discover and index your pages faster.

### Request re-indexing after major changes

After significant content updates, use [Google's URL Inspection tool](https://support.google.com/webmasters/answer/9012289) to request re-crawling. Search engines don't immediately reflect changes, so allow time for updates to appear in search results.
</Steps>

## Controlling search engine indexing

### Hide pages from search engines

Use `noindex` and `nofollow` in frontmatter to prevent search engines from indexing specific pages. This is useful for internal documentation, draft content, or pages you want accessible by URL only.

```mdx title="internal-notes.mdx"
---
title: Internal release notes
noindex: true
nofollow: true
---
```

<Info>
Pages with `noindex` or `nofollow` are also excluded from your site's internal search results powered by Algolia DocSearch.
</Info>

### Hide pages from navigation only

To keep pages accessible by URL and indexed by search engines but hidden from the sidebar, use `hidden: true` in your `docs.yml` navigation. See [hiding content](/learn/docs/customization/hiding-content) for details.

## Canonical URLs for versioned content

For sites with multiple versions, Fern automatically sets canonical URLs to the unversioned (default) path to consolidate SEO signals. For example, both `/v1/docs/getting-started` and `/docs/getting-started` point to the same canonical URL.

If you need to override this behavior for specific pages, set `canonical-url` in frontmatter:

```mdx title="v1-specific-feature.mdx"
---
title: V1-specific feature
canonical-url: https://docs.plantstore.dev/v1/docs/v1-specific-feature
---
```

## API Reference SEO

For auto-generated API Reference pages, SEO metadata comes from your API specification:

**Endpoint descriptions** in your OpenAPI spec become the meta description for each endpoint page. Write clear, keyword-rich descriptions for your most important endpoints.

```yaml title="openapi.yaml"
paths:
  /plants/{plantId}:
    get:
      summary: Get plant details
      description: Retrieve detailed information about a specific plant including care instructions, pricing, and availability.
```

**Operation summaries** are used as page titles. Keep them concise and descriptive.

## Common issues

### Google isn't showing my site name correctly

Set `og:site_name` in your `docs.yml` metadata configuration. Note that Google doesn't guarantee it will use your preferred site name. It considers multiple signals including Open Graph tags, page content, and structured data. Changes may take several weeks to appear in search results after Google re-crawls your site.

### Pages show "Discovered - not indexed" in Search Console

This status means Google found your pages but hasn't indexed them yet. To improve indexing:

1. Ensure each page has a unique, descriptive `title` and `description`
2. Add internal links to important pages
3. Submit your sitemap to Search Console
4. Request indexing for specific URLs using the URL Inspection tool

Google may choose not to index pages it considers low-value or duplicate. Focus on creating unique, high-quality content.

### Duplicate title warnings in SEO reports

Fern automatically populates `og:title` from your page's `title` field. If you explicitly set both `title` and `og:title` to the same value, some SEO tools report this as duplication. Only set `og:title` when you need a different title for social sharing than what appears on the page.
