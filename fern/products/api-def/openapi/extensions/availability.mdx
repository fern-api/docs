The `x-fern-availability` extension is used to mark the availability of an endpoint within your OpenAPI definition. The availability information propagates into the generated Fern Docs website as visual tags, SDKs, and [CLIs](/learn/cli-generator/get-started/openapi-extensions#availability-badges).

You can configure the `availability` of sections in your API Reference documentation in your [`docs.yml` file](/learn/docs/configuration/site-level-settings). 

## Endpoint

The options are:

| Value | Description | Tag |
| --- | --- | --- |
| `alpha` | Early experimental stage | `Alpha` |
| `beta` | Stable enough for early adopters | `Beta` |
| `preview` | Feature-complete but subject to change | `Preview` |
| `generally-available` | Stable and ready for production | `GA` |
| `deprecated` | No longer recommended for new use | `Deprecated` |
| `legacy` | Superseded but still supported | `Legacy` |

The example below marks that the `POST /pet` endpoint is `deprecated`.

```yaml title="x-fern-availability in openapi.yml" {4}
paths:
  /pet:
    post:
      x-fern-availability: deprecated
```

You can also provide a custom message with the extended syntax:

```yaml title="x-fern-availability with message in openapi.yml" {4-6}
paths:
  /pet:
    put:
      x-fern-availability:
        status: deprecated
        message: Use PATCH /pet instead.
```

## SDK output

Availability values propagate into generated TypeScript SDKs as JSDoc tags on client methods. IDEs surface these tags as warnings and strikethrough styling, so SDK consumers see availability status directly in their editor.

| Availability | JSDoc tag |
| --- | --- |
| `deprecated` | `@deprecated` |
| `deprecated` (with message) | `@deprecated Use PATCH /pet instead.` |
| `beta`, `pre-release` | `@beta This endpoint is in pre-release and may change.` |
| `in-development` | `@beta This endpoint is in development and may change.` |

For example, given this OpenAPI definition:

```yaml title="openapi.yml"
paths:
  /plants:
    post:
      x-fern-availability: beta
      operationId: createPlant
      summary: Add a plant to the catalog.
  /plants/{plantId}:
    get:
      x-fern-availability: deprecated
      operationId: getPlant
```

The generated TypeScript SDK client includes availability in the JSDoc comments:

```typescript title="Generated TypeScript SDK"
export class PlantsClient {
    /**
     * @beta This endpoint is in pre-release and may change.
     *
     * Add a plant to the catalog.
     */
    public createPlant(
        request: CreatePlantRequest,
        requestOptions?: PlantsClient.RequestOptions,
    ): Promise<PlantId> { ... }

    /**
     * @deprecated
     */
    public getPlant(
        plantId: PlantId,
        requestOptions?: PlantsClient.RequestOptions,
    ): Promise<Plant> { ... }
}
```

For a real-world example, see the [Square TypeScript SDK](https://github.com/square/square-nodejs-sdk/blob/master/src/api/resources/employees/client/Client.ts), where the deprecated `employees.list` and `employees.get` methods are marked with `@deprecated`.
