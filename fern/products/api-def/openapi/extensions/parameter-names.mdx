title: Customize parameter names
headline: Customize parameter names (OpenAPI)
description: Use `x-fern-parameter-name` to customize query parameter, header and path parameter naming.
---


<Note>
  The `x-fern-parameter-name` extension allows you to customize the variable names of parameters in your generated SDKs.
</Note>

## Headers

In the example below, the header `X-API-Version` is renamed to `version` in the
generated SDK. The rename makes the SDK more human readable.

```yaml {8}
paths:
  "/user":
    get:
      operationId: list_user
      parameters:
        - in: header
          name: X-API-Version
          x-fern-parameter-name: version
          schema:
            type: string
          required: true
```

## Query parameters

In the example below, the query parameter `q` is renamed to `search_terms` in the
generated SDK. The rename makes the parameter more approachable for end users.

```yaml {8}
paths:
  "/user/search":
    get:
      operationId: search_user
      parameters:
        - in: query
          name: q
          x-fern-parameter-name: search_terms
          schema:
            type: string
          required: false
```

## Path parameters

In the example below, the path parameter `userId` is renamed to `id` in the
generated SDK. The rename makes the SDK less verbose.

```yaml {8}
paths:
  "/user/{userId}":
    get:
      operationId: get_user
      parameters:
        - in: path
          name: userId
          x-fern-parameter-name: id
          schema:
            type: string
          required: false
```

## Resolve naming conflicts

`fern check` errors when a path parameter shares a name with another request property —
an inlined request body property, query parameter, or header — including collisions that
only appear after camelCase normalization. Rename one of the parameters with
`x-fern-parameter-name` to resolve the conflict.

In the example below, the path parameter `plantId` collides with the `plantId` property in
the request body. Renaming the path parameter to `id` deconflicts the two names.

```yaml {8}
paths:
  "/plants/{plantId}":
    post:
      operationId: update_plant
      parameters:
        - in: path
          name: plantId
          x-fern-parameter-name: id
          schema:
            type: string
          required: true
      requestBody:
        content:
          application/json:
            schema:
              type: object
              properties:
                plantId:
                  type: string
```
