---
title: API Explorer control
subtitle: Control API Explorer availability using `x-fern-explorer` extension
---

The `x-fern-explorer` extension allows you to control whether the API Explorer (interactive API playground) is available in your documentation. You can disable it globally for your entire API or selectively for specific endpoints.

## Global configuration

To disable the API Explorer for your entire API, add the `x-fern-explorer` extension at the root level of your OpenAPI specification:

```yaml title="openapi.yml" {2}
openapi: 3.0.0
x-fern-explorer: false
info:
  title: My API
  version: 1.0.0
paths:
  /users:
    get:
      operationId: list_users
```

When set to `false`, the API Explorer will be disabled for all endpoints in your documentation. By default, the API Explorer is enabled (`true`) if this extension is not specified.

## Endpoint-level configuration

To control the API Explorer for individual endpoints, use the `x-fern-explorer-enabled` extension on specific operations:

```yaml title="openapi.yml" {5,14}
paths:
  /users:
    get:
      operationId: list_users
      x-fern-explorer-enabled: true
      responses:
        '200':
          description: List of users
  /users/{userId}:
    delete:
      operationId: delete_user
      parameters:
        - name: userId
          in: path
          required: true
          schema:
            type: string
      x-fern-explorer-enabled: false
      responses:
        '204':
          description: User deleted
```

In this example:
- The `GET /users` endpoint has the API Explorer enabled
- The `DELETE /users/{userId}` endpoint has the API Explorer disabled

## Use cases

Common scenarios for disabling the API Explorer include:

- **Destructive operations**: Disable the playground for endpoints that delete data or perform irreversible actions
- **Payment processing**: Prevent users from accidentally triggering real transactions in your documentation
- **Admin-only endpoints**: Hide the playground for sensitive administrative operations
- **Complex authentication**: Disable for endpoints that require complex authentication flows that are difficult to test in the playground

## Combining global and endpoint-level settings

You can combine both extensions to set a default behavior globally and override it for specific endpoints:

```yaml title="openapi.yml" {2,11,20}
openapi: 3.0.0
x-fern-explorer: false
info:
  title: My API
  version: 1.0.0
paths:
  /users:
    get:
      operationId: list_users
      # Explorer disabled by default (global setting)
      x-fern-explorer-enabled: true  # Override: enable for this safe read operation
  /users/{userId}:
    delete:
      operationId: delete_user
      parameters:
        - name: userId
          in: path
          required: true
          schema:
            type: string
      # Explorer disabled by default (global setting applies)
```

In this example, the API Explorer is disabled globally, but explicitly enabled for the safe `GET /users` endpoint while remaining disabled for the destructive `DELETE` operation.
