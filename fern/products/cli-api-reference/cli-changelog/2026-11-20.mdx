## 5.226.0
**`(fix):`** `fern generate` now writes every file of a generated SDK on Node 24. Before, unpacking the download could stop partway through a large file without an error, so the files after it were missing (for example, a generated CLI missing `src/output.rs` and failed to compile) while the command still reported success.


**`(feat):`** `fern init` on its own in a terminal now starts the setup wizard: it finds your API spec and coding agents, checks your organization name, and sets up the project, a docs site with your company's branding, coding-agent instructions, docs publishing, and SDKs, asking before each step. `fern init` with flags, or outside a terminal, works as before.


**`(feat):`** Add standalone commands for the wizard's steps: `fern docs brand <company>` (your company's logo, favicon, and accent color in docs.yml), `fern docs url check <name>`, `fern org check <name>`, `fern org create <name>`, `fern agent setup`, and `fern detect`. `fern init --docs --template stacked|side-by-side|minimal` starts from Fern's docs starter, downloaded on first use.


**`(feat):`** The `fern init` setup wizard now asks what to set up with a checklist of SDKs, Docs, and CLI. Picking CLI adds a `cli` target to `fern/sdk-config.yml` and generates it into `cli/` in the same step as SDKs.


**`(fix):`** The `fern init` setup wizard's docs site now keeps the docs starter and your company's logo, favicon, and accent color. Before, the API step also created a basic docs.yml first, which the starter left in place, and new projects with `fern/sdk-config.yml` also got the starter's sample Plant Store API.


**`(fix):`** When your Fern login has expired, the `fern init` setup wizard now signs you in again and repeats the brand search, instead of skipping your company's branding.


**`(feat):`** The `fern init` setup wizard now shows the logo, favicon, and accent color it found for your company and asks before using them, so you can choose a different company or keep the starter branding.


**`(fix):`** The `fern init` setup wizard now generates only the `fern/sdk-config.yml` targets it set up (SDKs and the CLI), so another target in the file, such as an MCP server, can't stop them from generating.


**`(fix):`** When a `fern` command fails during the `fern init` setup wizard, the wizard now shows the reason Fern printed after the error and saves the command's full output to `~/.fern/logs/`.


**`(fix):`** In a new project, the `fern init` setup wizard now lets you uncheck TypeScript when picking SDK languages. Before, it showed the TypeScript target that `fern init` adds to every new `fern/sdk-config.yml` as "already set up" and always generated it.


**`(fix):`** The `fern init` setup wizard now pins new projects to the newest released Fern CLI, even when run from an unreleased build. SDKs are now generated on Fern's servers from `sdk-config.yml` targets, and `fern agent setup` writes the Fern skill next to the fern-docs skill.


**`(fix):`** `fern init --docs --template` falls back to Fern's basic docs site when the docs starter can't be downloaded, and `--no-docs --template` is rejected like `--template` without `--docs`.


**`(feat):`** The `fern init` setup wizard works without a Fern account. When you aren't signed in, its first step asks whether to sign in, continue without an account, or skip; `fern init --guest` picks the second from the start. Without an account the wizard publishes your docs to a temporary site and generates your SDKs with `fern generate --guest`, and ends with the link that claims both into your Fern organization (where you pick its name and your docs URL), plus the session's expiry.


**`(chore):`** Show the Fern logo above the heading on the page `fern login` opens after you sign in.


## 5.225.0
**`(feat):`** MCP targets now accept `instructions` and `appendInstructions` in the SDK Config `generation`
block (`@postman/sdk-config` 0.25.0). `instructions` replaces the server instructions returned
on `initialize`; `appendInstructions` appends to the generated ones. Previously these keys were
rejected during SDK Config validation.
