## 5.155.6
**`(fix):`** `fern export` no longer marks `optional<T>` object properties (including union variant values and
multipart form fields), query parameters, headers, and request bodies as `nullable: true`. Optionality is already expressed by leaving them out of `required`, so the
extra flag turned every `optional<T>` into `optional<nullable<T>>` when the spec was imported or used
to generate an SDK. `nullable<T>` and `optional<nullable<T>>` still export with `nullable: true`, as do
`optional<T>` list items, map values, aliases, and responses, where `null` is how an absent value is sent.


## 5.155.5
**`(fix):`** SDK Config GitHub delivery through sdk-gen-api now reports its outcome. The CLI prints the pull
request link when one is created, says explicitly when no changes were detected and nothing was
delivered, and fails instead of reporting success when sdk-gen-api never confirms the delivery.


## 5.155.4
**`(fix):`** `fern sdk migrate` now keeps publish usernames written as plain text (such as the PyPI token
username `__token__`) instead of dropping them, which made `fern generate` fail with "Direct
pypi publication through sdk-gen-api requires username". Maven usernames are still omitted
unless they are environment variables, because Sonatype user tokens make them secret.


## 5.155.3
**`(fix):`** Add `algorithm-header` to HMAC `webhook-signature` blocks (including
`api.settings.webhook-signature`). It names a request header whose value selects the
HMAC algorithm per request, optionally prefixed by a key ID
(e.g. Twilio's `X-Twilio-Webhook-Signature-Settings: <key_id>;HMAC_SHA256`), and maps the
allowed header values (`HMAC_SHA1`, `HMAC_SHA256`) to algorithms. Compiled into
`HmacSignatureVerification.algorithmHeader` in the IR so generated verifiers can read the
algorithm and key ID from the request themselves.


## 5.155.2
**`(fix):`** Each feature flag evaluation now also sends a `feature_flag_evaluated` event with the same
properties (`org`, `environment`, `generator`, `language`, `version`) and the flag `response`
and `enabled` result. PostHog keeps only about one `$feature_flag_called` per org, flag, and
value per hour, so that event cannot count evaluations per generator; this one can.


**`(fix):`** `fern generate` now routes SDK Config runs and generator versions at or past their SDK Config
cutover (for example TypeScript 4.0.0+, Python 6.0.0+) through sdk-gen-api regardless of the
`use-sdk-gen-api` feature flag, which now only governs earlier versions. A post-cutover version
configured in generators.yml always fails before generation with the `fern sdk migrate` /
`--sdk-config` error, instead of being sent to legacy generation when the flag is off.
`FERN_USE_SDK_GEN_API=false` still turns sdk-gen-api off, and `fernapi/fern-mcp-server` remains
gated by the flag.
