## 5.143.0
**`(feat):`** Make `fern sdk migrate` apply reversible group and language level migrations, preserve rollback YAML in `generators.legacy.yml`, merge compatible SDK Config targets, and support dry runs.


## 5.142.0
**`(feat):`** `experimental.external-sitemaps` entries may now be objects with a `url` and an
optional `locale`, e.g. `- url: https://help.example.com/sitemap.xml` /
`locale: nl`. When set, every page in that sitemap is indexed into the search
index of that site locale instead of relying on per-URL language detection.


## 5.141.2
**`(fix):`** Reject `fern generate --sdk-config` when a selected target pins a generator version from before that language's SDK Config cutover.


## 5.141.1
**`(fix):`** Bump bundled @fern-api/generator-cli to 0.10.3. When the hosted auto-version analysis of the
full SDK diff fails, generator-cli now retries chunk-by-chunk instead of silently applying a
PATCH bump; any remaining unavailable or incomplete analysis adds a "Version bump not verified"
notice to the SDK PR body and disables automerge.


## 5.141.0
**`(feat):`** Support selecting SDK Config targets with `fern generate --target`, including mixed generation with legacy `--group` selections, per-API `sdk-config.yml` discovery, explicit `--sdk-config` overrides, and the provisional `generators.legacy.yml` filename. With no selectors, generation runs the legacy default group and every target in the default SDK Config, while `--local` continues to run legacy generation only. SDK Config generation is labeled by target (for example, `Python SDK`) instead of exposing the internal legacy-style generator identifier, and `fern check` validates SDK Config-only API sources.


## 5.140.2
**`(fix):`** Stop uploading direct publish credentials for SDK Config GitHub outputs. GitHub
delivery with registry publication now omits the sdk-gen-api credentials
multipart file, matching server expectations for GitHub/Actions-based publishing.


**`(fix):`** Forward GitHub output options (`replay`, `verify`, and `skipIfNoDiff`) in
sdk-gen-api requests. Previously, GitHub generations routed through sdk-gen-api
could submit without replay settings from generators.yml.


## 5.140.1
**`(fix):`** Fix custom MDX components that import third-party packages failing to render with
`Could not resolve "../node_modules/..."`. Relative imports inside bundled packages
(e.g. barrel files like `export * from "./Button/index.js"`) are now bundled instead of
left external, and `require("react")` calls from bundled CommonJS dependencies no longer
throw `Dynamic require of "react" is not supported` in the docs renderer.
