## 5.193.0
**`(feat):`** Remote generation now sends SHA-256 digests of its inputs to Fiddle: every spec, overlay and
overrides file referenced by `generators.yml`, `generators.yml` itself, and the generator's
entry in it. Fiddle uses them to build a signed provenance record for the generated SDK.


## 5.192.0
**`(feat):`** `fern docs md generate` now keeps LaTeX math (`$…$` and `$$…$$`) in Python library
docstrings intact instead of escaping its braces, shows `{`, `<` and `>` inside inline
code literally instead of as `&#123;`/`&lt;`, and renders `> [!NOTE]`-style alerts
(which the Python parser now emits for reStructuredText admonitions) as Fern callouts.


## 5.191.2
**`(fix):`** `fern generate` now builds SDKs for proto (gRPC) APIs in `generators.yml` on Fern's original
generation service, so `fern init --grpc` followed by `fern generate` works without setting
`FERN_USE_SDK_GEN_API=false`.


## 5.191.1
**`(fix):`** `fern init --grpc` and `fern init --proto <path>` no longer fail with "gRPC initialization is not supported by
this version of fern init". They now always write a `generators.yml`, since SDK Config does not support gRPC yet.


## 5.191.0
**`(feat):`** Point unauthenticated non-interactive runs at `--guest`. `fern generate --docs` run without a login or
`FERN_TOKEN` from a script or agent now fails on the missing account first (naming `--guest` as the way to publish
without one) instead of on the production-site confirmation, and no longer prints the site URL with a doubled
`https://`. `fern init` without `--organization` in non-interactive mode derives the organization from the
directory name instead of failing, and `fern init --docs` prints the publish command to run next
(`fern generate --docs --guest` when there is no account).
