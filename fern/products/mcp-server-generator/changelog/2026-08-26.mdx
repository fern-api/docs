## Schema-driven MCP server generation

<ChangelogTags>features</ChangelogTags>

The MCP server generator is rebuilt around a schema-driven architecture. Each API operation becomes a tool whose JSON Schema input is derived from its OpenAPI definition, and generated packages contain one editable handler module per tool under `src/tools/`, a tool manifest at `src/manifest.ts`, a fetch-based runtime at `src/runtime.ts`, and editable request and response hooks at `src/hooks.ts`. Generated servers target `@modelcontextprotocol/server` 2.0.0 over stdio.

## Full-fidelity tool input schemas

<ChangelogTags>features</ChangelogTags>

Tool input schemas cover primitives with their validation rules, arrays, dictionaries, enums, `oneOf`/`anyOf`/`allOf` composition, discriminators, nullable schemas, and recursive models. Constructs JSON Schema can't represent exactly — mixed types, `patternProperties`, and `if`/`then` conditionals — are relaxed to accept a superset and explained in the tool description. 64-bit integers also accept decimal strings, so values above 2<sup>53</sup> survive JavaScript's number precision.

## Toolsets selected at startup

<ChangelogTags>features, generators.yml</ChangelogTags>

The `MCP_TOOLSET` environment variable selects which toolset a server loads at startup, so a client can register a large API as several small tool surfaces. Toolsets are derived per service and per tag automatically. Entries under `mcpConfig.toolsets` override the derived names, and `mcpConfig.tools` include and exclude filters plus `mcpConfig.excludeAvailability` prune the tool list before anything is generated.

## Credential environment variables per security scheme

<ChangelogTags>auth</ChangelogTags>

Credential environment variables are named after the spec's security schemes, so multiple schemes stay independent. A scheme named `widgetKey` reads `WIDGET_KEY`, and an HTTP Basic scheme named `basicAuth` reads `BASIC_AUTH_USERNAME` and `BASIC_AUTH_PASSWORD`.

## Documentation resources and server instructions

<ChangelogTags>features</ChangelogTags>

Generated servers expose the prose from your API definition as MCP resources: a guide per tag, a guide and examples per operation, and an error taxonomy covering every documented failure. Server instructions built from the same definition tell the client how to route a call, how authentication works, and how to read the schemas.
