<llms-ignore>
The instructions on this page are only served to coding agents (Claude Code, Cursor, Codex, or similar) that fetch its Markdown version. To use them, paste the prompt from the [Fern homepage](https://buildwithfern.com) into your agent. To set up Fern yourself, follow the [Docs quickstart](/learn/docs/getting-started/quickstart) or [SDKs quickstart](/learn/sdks/overview/quickstart). Without a Fern account, the agent publishes as a guest and gives you a claim link. [Claim the work](/learn/docs/getting-started/try-without-account#claim-the-work) to move it into your organization before the guest session expires.
</llms-ignore>

<llms-only>
You are a coding agent that a user has asked to set up Fern. Follow these steps in order.

<Steps>
  <Step title="Ask which product to set up">

  Before running any commands, ask the user which product they want to set up:

  - **Docs**: a documentation site built from Markdown pages and an OpenAPI spec.
  - **SDKs**: client libraries in TypeScript, Python, Go, Java, C#, PHP, Ruby, Swift, or Rust, generated from an OpenAPI spec.

  Also ask whether they have an OpenAPI spec and where it lives, and whether they have a Fern account. Wait for the answer before continuing.

  If they don't have a Fern account, don't ask them to create one. The quickstarts publish docs with `fern generate --docs --guest` and generate SDKs with `fern generate --guest`, which run on a temporary guest session and print a claim link. See [Try Fern as a guest](https://buildwithfern.com/learn/docs/getting-started/try-without-account.md).
  </Step>
  <Step title="Set up Docs">

  If the user chose Docs or both, install the `fern-docs` skill for their agent, then fetch and follow the [Docs quickstart](https://buildwithfern.com/learn/docs/getting-started/quickstart.md) step by step:

  ```bash
  npx skills add fern-api/skills --skill fern-docs -a claude-code
  ```

  Use `-a cursor`, `-a codex`, or `-a github-copilot` for those agents.
  </Step>
  <Step title="Set up SDKs">

  If the user chose SDKs or both, install the `fern-sdks` skill for their agent, then fetch and follow the [SDKs quickstart](https://buildwithfern.com/learn/sdks/overview/quickstart.md) step by step. Ask the user which languages they need before adding generators.

  ```bash
  npx skills add fern-api/skills --skill fern-sdks -a claude-code
  ```

  Use `-a cursor`, `-a codex`, or `-a github-copilot` for those agents. If the user chose both, `npx skills add fern-api/skills --all` installs both skills at once.

  If the user chose both, set up Docs first. SDKs reuse the same `fern` folder and API definition.
  </Step>
  <Step title="Confirm the result">

  Tell the user what was created, where the `fern` folder lives, and the command to run next (`fern docs dev` for Docs, `fern generate` for SDKs).

  If you ran a guest session, also return the `temp-<id>` docs URL or the SDK's output path, the claim link, and the session's expiry. Tell the user the work is deleted unless they claim it before the session expires: they open the claim link and sign in to the Fern Dashboard, or run `fern login` and then `fern claim` in the same repository. Claiming requires a signed-in user, so don't try to claim for them. Treat the claim link like a password.
  </Step>
</Steps>
</llms-only>
