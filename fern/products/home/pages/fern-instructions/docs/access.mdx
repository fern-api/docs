---
title: Restrict access to Fern docs
slug: fern-instructions/docs/access
description: Gate Fern docs with a password, SSO, JWT, or OAuth, show content by role with RBAC, and inject readers' API keys into the API Explorer.
---

Use this to make some or all of a site private.

## Pick a method

| Need | Method |
|---|---|
| Quick gate with a shared password, no per-user accounts | Password protection (several passwords can map to roles) |
| Internal docs behind the company's login (Okta, Google Workspace and others) | SSO |
| Use the product's own login and control the flow yourself | JWT |
| Use the product's own login, with Fern running the flow through the OAuth provider | OAuth |

JWT, OAuth and SSO set a `fern_token` cookie that tells Fern who the reader is and which roles they have. Add RBAC to show different pages, sections or content to different roles, and API key injection to pre-fill the reader's key in the API Explorer.

## Workflow

1. Confirm the method with the user. Most methods need setup by Fern or values only the user has, such as an identity provider, a signing secret or OAuth client credentials. Don't invent them.
2. Follow the setup page for that method.
3. For RBAC, define roles in `docs.yml` and restrict navigation entries or page content to them, as described on the RBAC page.
4. Preview with `fern docs dev`. It includes a role selector and password login for sites that use them.

## Rules

- Never commit secrets such as JWT signing keys to the repo.
- Hiding a page (`hidden: true`) doesn't protect it. Anyone with the URL can open it. Use one of the methods above for content that must stay private.

## Verify

- Signed out, protected pages redirect to login or ask for the password. Signed in with each role, the reader sees exactly that role's content.
