Use this to add or change generated API Reference pages.

## Workflow

1. Make sure the spec is in the `fern/` folder and valid (`fern check`). Fix spec problems in the spec. See `spec`.
2. Point the docs at the spec. Either list it in `generators.yml`:

   ```yaml title="generators.yml"
   api:
     specs:
       - openapi: ./openapi.yml
   ```

   or reference it straight from navigation, in which case Fern ignores `generators.yml` for this reference:

   ```yaml title="docs.yml"
   navigation:
     - api: API Reference
       specs:
         - type: openapi
           path: ./openapi.yml
   ```

3. Add `- api: API Reference` to navigation if it isn't there. With several APIs in separate folders, add one entry each with `api-name: <folder>`.
4. Adjust the layout on the `api` entry: order sections and endpoints, rename or flatten sections, paginate, hide endpoints, add overview pages, custom sections, pages and links. Use `audiences` to publish a subset of endpoints.
5. Run `fern check` and review in `fern docs dev`. Use `--skip-api` to skip API pages when you're only editing prose.

## Rules

- Generated endpoint pages can't be edited as MDX. Change descriptions and examples in the spec, an overlay, or an override.
- Add request and response examples to the spec. Otherwise Fern generates them with AI.
- WebSocket and webhook references come from AsyncAPI and OpenAPI `webhooks`; gRPC, GraphQL and OpenRPC each have their own setup page.
- Links to endpoint pages follow the API Reference navigation, not the spec's paths.

## Verify

- Every endpoint you expect appears, with examples, and the API Explorer sends requests to the right base URL.
