Use this when a page needs more than Markdown. Fern components are available in every `.mdx` page without imports.

## Pick a component

| Need | Component |
|---|---|
| Aside the reader must not miss | `<Note>`, `<Tip>`, `<Info>`, `<Warning>`, `<Error>`, `<Success>`, `<Check>`, `<Launch>` |
| Ordered procedure | `<Steps>` with `<Step title="...">` |
| Alternatives (languages, platforms) | `<Tabs>` with `<Tab title="...">` |
| Optional or long detail | `<AccordionGroup>` with `<Accordion title="...">` |
| Links to other pages | `<CardGroup>` with `<Card title="..." href="...">` |
| Code | Fenced code blocks with a `title`; `<CodeBlocks>` for one example in several languages |
| Parameters or fields | `<ParamField path="..." type="...">` |
| Request or response from the API definition | `<EndpointRequestSnippet>`, `<EndpointResponseSnippet>`, `<EndpointSchemaSnippet>`, `<RunnableEndpoint>` |
| File tree | `<Files>` with `<Folder>` and `<File>` |
| Images with captions | `<Frame>` |
| Hover definitions | `<Tooltip>` |
| Content for some readers only | `<If>` |
| Prompt to copy into an AI tool | `<Prompt>` |

## Rules

- Use a component only when it helps the reader. A paragraph is usually better than a one-line callout.
- Don't wrap a single link in a callout. Put the link in a sentence.
- Anchor links don't work for component `title` props. Use a `##` heading when something needs a stable anchor.
- Mintlify components mostly work as-is or through aliases. Prefer the Fern names when editing.
- Check the component's page for props before using one. Don't invent props.

## Verify

- `fern check` passes, and the page renders in `fern docs dev` without MDX errors.
