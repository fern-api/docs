Use this when `docs.yml` settings aren't enough. Try `docs configure` first.

## Workflow

1. Custom CSS: create `fern/styles.css` and add `css: ./styles.css` to `docs.yml`. `css` also takes a list of files. Target elements with the selectors in the CSS selectors reference.
2. Custom JavaScript: add `js: ./custom.js` to `docs.yml`.
3. Custom React components: write the component in the project, list its folder under `experimental.mdx-components` in `docs.yml`, then use it in MDX like a built-in component. These render on the server and are indexed by search engines; scripts added with `js` aren't.
4. Announcement banner: add an `announcement` block with a `message` to `docs.yml`.
5. Hide content: `hidden: true` on a navigation entry, or `noindex: true` in page frontmatter. See `docs configure navigation`.
6. Run `fern check`, then check every change in `fern docs dev` in light and dark mode.

## Rules

- Use built-in settings (colors, layout, theme) before custom CSS. Selectors not in the reference can change without notice.
- Don't load third-party scripts for analytics with `js`. Use the built-in integrations. See `docs analytics`.
- Prefer React components over `js` for content readers or search engines need to see.

## Verify

- `fern docs dev` shows the change with no console errors, on desktop and mobile widths.
