Use this to change metadata, URLs, redirects, or crawler access.

## Workflow

1. Metadata: set `title` and `description` in each page's frontmatter. Site-wide defaults go in the `metadata` section of `docs.yml`.
2. Slugs: set `slug:` on a navigation entry, or in page frontmatter to override the whole path.
3. Redirects: whenever a published URL changes, add an entry to `redirects` in `docs.yml`:

   ```yaml
   redirects:
     - source: "/learn/old-path"
       destination: "/learn/new-path"
     - source: "/learn/old-section/:slug*"
       destination: "/learn/new-section/:slug*"
   ```

   Redirects are permanent (308) by default. Add `permanent: false` for a temporary (307) redirect. Large sites can move redirects to separate files, each with a top-level `redirects` list.
4. Run `fern check`. It warns when a moved or removed page has no redirect.

## Rules

- Include the base path (such as `/learn`) in `source` and `destination`.
- Don't create loops or chains. `fern check` fails on a redirect whose source equals its destination, or on a circular chain.
- Set `metadata.canonical-host` in `docs.yml` when the site is reachable at more than one domain.
- `hidden: true` on a section, tab, or version only hides it from navigation; its pages stay indexed unless each sets `noindex: true`.
- `hidden: true` on a page removes it from the sidebar and search and sets `noindex`. `noindex: true` in frontmatter keeps the page in the sidebar but out of search engines and `llms.txt`.

## Verify

- `fern check` passes with no redirect warnings.
- After publishing, the old URL returns a redirect to the new one.
