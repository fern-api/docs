Use this to see a change before it ships, or to ship it.

## Workflow

1. Validate: `fern check`.
2. Preview locally: `fern docs dev`. It hot-reloads and needs no login. On large sites, `--skip-api` skips parsing API specs and `--skip-validation` skips validation. Use `--port` to change the port.
3. Share a preview: `fern generate --docs --preview`. Add `--id <name>` for a stable URL (`<org>-preview-<name>.docs.buildwithfern.com`) that each run overwrites. Outside GitHub Actions, add `--force` or `--no-prompt` to skip the overwrite prompt. List and delete previews with `fern docs preview list` and `fern docs preview delete`.
4. Publish: `fern generate --docs`. With several `instances` in `docs.yml` (for example staging and production), choose one with `--instance <url>`.
5. Without a Fern account, `fern generate --docs --guest` publishes to a temporary Fern Drop site. See `new-site`.

## Rules

- Publishing and preview links need `fern login`, `FERN_TOKEN`, or `--guest`. `fern docs dev` and `fern check` don't.
- `fern generate --docs` fails on any `fern check` rule set to `error`.
- In CI, set `FERN_TOKEN` and pass `--no-prompt`. See `automate`.
- Don't publish to production when the user asked for a preview.
- After `fern docs theme upload`, sites using that `global-theme` keep the old theme until they publish again. `fern docs theme rebuild` rebuilds them without a publish. It needs an org admin. Run `--dry-run` first to list the sites.

## Verify

- The command prints `Published docs to <url>`. Open that URL and confirm the change.
- For production, check the page on the custom domain too, if there is one.
