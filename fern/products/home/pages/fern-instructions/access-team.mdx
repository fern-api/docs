Use this for organization-level access, not for gating docs readers (see `docs access`).

## Workflow

1. Check the identity in use with `fern whoami`.
2. Members and roles are managed in the [Fern Dashboard](https://dashboard.buildwithfern.com). The user does this in the browser.
3. Tokens for CI: `fern token` creates one. `fern org token list`, `fern org token create` and `fern org token revoke` manage them.
4. Organization settings: `fern org get` shows them, and `fern org set cli-version` / `fern org unset cli-version` control the CLI version policy.
5. Dashboard settings cover SSO, API keys, the connected GitHub repo, custom domains, password protection and PDF export.

## Rules

- Only organization admins can change members, tokens and settings. If a command fails with a permission error, the user needs an admin.
- Revoke tokens that leak or are no longer used.
