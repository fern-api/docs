Use this to move an SDK from local output to a GitHub repo and a package registry.

## Workflow

1. Create one GitHub repository per SDK and install the [Fern GitHub App](https://github.com/apps/fern-api) on it.
2. Set the target's output to GitHub and add publishing in `sdk-config.yml`:

   ```yaml
   targets:
     - language: typescript
       package:
         packageName: "@acme/sdk"
       output:
         delivery: github
         github:
           repository: acme/acme-typescript
           mode: pull-request
         publish:
           registry: npm
           token: ${NPM_TOKEN}
   ```

   `mode` is one of `release`, `pull-request`, `push`, `commit` or `commit-and-release`. Legacy `generators.yml` projects configure the same thing under each generator's `output` and `github`.
3. Add the registry credential as a GitHub Actions secret in the SDK repo (for example `NPM_TOKEN`). npm also supports trusted publishing (OIDC) with `trustedPublishing: true` instead of a token.
4. Generate with a version: `fern generate --target typescript --version 1.2.0`. Without `--version`, Fern picks one.
5. Merge the generated pull request (or let `release` mode publish). The SDK repo's workflow publishes the package.

## Rules

- Credentials must be environment expressions such as `${NPM_TOKEN}`, never literal values.
- Package names must be available on the registry. Ask the user before choosing one.
- A guest session (`fern generate --guest`) can generate and download an SDK but can't push it to GitHub or publish it to a registry. Claim the session or log in first; after the claim, the SDK's card in the Fern Dashboard offers Publish to GitHub and Set up Fern repository. See `new-site`.
- If a release exists but the package isn't on the registry, debug the publish workflow in the SDK repo.

## Verify

- The SDK repo has the generated commit or pull request, and the package version appears on the registry after the workflow runs.
