Use this to generate without Fern's servers, try an SDK before publishing, or test it.

## Workflow

1. Preview without publishing: `fern generate --preview` (or `--target <language> --preview`). Output goes to `fern/.preview/` (`--output <dir>` to change it) and nothing is pushed or published.
2. Run generators on the user's machine: `fern generate --local`. This needs a running Docker daemon (or another runtime selected with `--runner`). `sdk-config.yml` targets run Fern's on-prem generator locally and need a minimum generator version per language.
3. Point output at a folder with `output.delivery: files` and `output.path` in `sdk-config.yml`, then build or install the SDK from there.
4. Test the SDK against the API, or against generated tests and mocks, as described in the testing page.
5. For air-gapped or regulated environments, follow the self-hosted generation pages.

## Rules

- Without `generatorVersion`, local runs use the minimum supported version while remote runs use the newest. Pin it so local and remote output match.
- `fern generate --package` builds an installable artifact (for example `.tgz` or `.whl`) in `fern-dist/` for targets with file output.
- On CI runners without Docker, use remote generation.

## Verify

- The SDK builds and its tests pass in the output folder.
