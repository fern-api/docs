Use this when the API isn't (only) described with OpenAPI.

## Formats

| Format | Use for | Notes |
|---|---|---|
| AsyncAPI | WebSocket and event APIs | Channels, messages and bindings map to WebSocket clients and reference pages. Supports Fern extensions such as audiences and availability. |
| gRPC | Protobuf services | Point the project at the `.proto` root. `fern init --grpc` (sample) or `fern init --proto <path>` creates a project with a C# SDK, the only SDK language with native gRPC output. |
| OpenRPC | JSON-RPC APIs | Methods become SDK methods. Has its own extensions. |
| Fern Definition | APIs defined directly in Fern's YAML format | `fern init --fern-definition` creates a sample. |

## Workflow

1. Add the definition to the `fern/` folder and list it with its type, for example `asyncapi: ./asyncapi.yml` under `api.specs` in `generators.yml`, or `type: asyncapi` in `sdk-config.yml` and `docs.yml` spec entries.
2. Run `fern check`.
3. Preview with `fern docs dev` or `fern generate --preview`.

## Rules

- OpenAPI and AsyncAPI specs can sit side by side in one API. That's how to describe REST plus WebSocket.
- Check the format's extensions page before adding `x-fern-*` keys. Not every OpenAPI extension exists for every format.
