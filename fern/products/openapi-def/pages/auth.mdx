Configuring authentication schemes in your OpenAPI definition allows you to control how users authenticate with your API. All Fern-generated SDKs support both direct configuration and environment variables for authentication credentials.

## Authentication Methods Overview

Authentication is configured in the `components.securitySchemes` section of your OpenAPI spec:

```yml title="openapi.yml" {2-3}
components: 
  securitySchemes: 
    ...
```

<Note>
To apply a security scheme across all endpoints, reference the `securityScheme` within the `security` section of your OpenAPI Specification. 

```yml title="openapi.yml" {3, 5-6}
components: 
  securitySchemes: 
    AuthScheme:
      ...
security: 
  - AuthScheme: []
```
</Note>

## Environment Variable Support

All authentication methods in Fern-generated SDKs support environment variables by default. You can:

1. Configure custom environment variable names
2. Fall back to direct configuration when environment variables aren't present
3. Override environment variables with direct configuration

This flexibility allows your SDK users to:
- Use environment variables in production
- Hard-code credentials in development
- Mix and match as needed

## Bearer security scheme

Start by defining a `bearer` security scheme in your `openapi.yml`: 

```yml title="openapi.yml" {3-8}
components:
  securitySchemes:
    BearerAuth:
      type: http
      scheme: bearer
      x-fern-bearer: 
        name: apiKey
        env: PLANTSTORE_API_KEY
```

SDK users can authenticate using either approach:

```ts index.ts
// Option 1: Use environment variable PLANTSTORE_API_KEY
let client = new Client(); 

// Option 2: Direct configuration (overrides environment variable)
client = new Client({
  apiKey: "ey34..."
})
```

## Basic security scheme

Define a `basic` security scheme with environment variable support: 

```yaml title="openapi.yml" {3-12}
components:
  securitySchemes:
    BasicAuth:
      type: http
      scheme: basic
      x-fern-basic:
        username:
          name: clientId
          env: PLANTSTORE_CLIENT_ID
        password:
          name: clientSecret
          env: PLANTSTORE_CLIENT_SECRET
```

SDK users can authenticate using either approach:

```ts index.ts
// Option 1: Use environment variables PLANTSTORE_CLIENT_ID and PLANTSTORE_CLIENT_SECRET
let client = new Client(); 

// Option 2: Direct configuration (overrides environment variables)
client = new Client({
  clientId: "joeschmoe", 
  clientSecret: "ey34..."
})
```

## ApiKey security scheme

Define an `apiKey` security scheme with environment variable support:

```yaml title="openapi.yml" {3-10}
components: 
  securitySchemes: 
    ApiKey: 
      type: apiKey
      in: header
      name: X_API_KEY
      x-fern-header:
        name: apiToken
        env: PLANTSTORE_API_KEY
        prefix: "Token " # Optional      
```

SDK users can authenticate using either approach:

```ts index.ts
// Option 1: Use environment variable PLANTSTORE_API_KEY
let client = new Client(); 

// Option 2: Direct configuration (overrides environment variable)
client = new Client({
  apiToken: "ey34..."
})
```

## Multiple security schemes

You can define multiple security schemes with environment variables by listing them under `components.securitySchemes`:

```yaml title="openapi.yml" {3-15}
components: 
  securitySchemes: 
    BearerAuth:
      type: http
      scheme: bearer
      x-fern-bearer:
        name: bearerToken
        env: API_BEARER_TOKEN
    ApiKey: 
      type: apiKey
      in: header
      name: X_API_KEY
      x-fern-header:
        name: apiKey
        env: API_KEY
```

The SDK will check for the specified environment variables first, then fall back to direct configuration if needed.

<Note>
Environment variable names are case-sensitive. Make sure to use the exact names specified in your OpenAPI definition.
</Note>
