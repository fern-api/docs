<Note>
  These extensions give you fine-grained control over parameter naming and behavior in your generated SDKs.
</Note>

## x-fern-parameter-name

The `x-fern-parameter-name` extension allows you to customize the variable names of parameters in your generated SDKs.

### Headers

In the example below, the header `X-API-Version` is renamed to `version` in the generated SDK for better readability:

```yaml {8}
paths:
  "/user":
    get:
      operationId: list_user
      parameters:
        - in: header
          name: X-API-Version
          x-fern-parameter-name: version
          schema:
            type: string
          required: true
```

### Query parameters 

Here, the query parameter `q` is renamed to `search_terms` to make it more descriptive:

```yaml {8}
paths:
  "/user/search":
    get:
      operationId: search_user
      parameters:
        - in: query
          name: q
          x-fern-parameter-name: search_terms
          schema:
            type: string
          required: false
```

### Path parameters

The path parameter `userId` is renamed to `id` for more concise SDK usage:

```yaml {8}
paths:
  "/user/{userId}":
    get:
      operationId: get_user
      parameters:
        - in: path
          name: userId
          x-fern-parameter-name: id
          schema:
            type: string
          required: false
```

## x-fern-sdk-variables

The `x-fern-sdk-variables` extension allows you to specify variables that will be injected via the SDK client constructor, rather than requiring them as parameters on each individual endpoint.

```yaml
components:
  x-fern-sdk-variables:
    project_id:
      type: string 
      description: The ID of the project
      pattern: "^proj_[a-zA-Z0-9]+$"

paths:
  /v1/connect/{project_id}/accounts:
    parameters:
      - name: project_id
        in: path
        required: true
        schema:
          type: string
          pattern: "^proj_[a-zA-Z0-9]+$"
        x-fern-sdk-variable: project_id
```

In this example:

1. The `project_id` variable is defined under `x-fern-sdk-variables`
2. Individual endpoints reference this variable using `x-fern-sdk-variable: project_id`
3. The SDK will accept `project_id` in the client constructor and automatically inject it into path parameters

This means instead of passing `project_id` on every API call, you can configure it once when initializing the client:

```python
client = Client(project_id="proj_123")
client.accounts.list() # project_id automatically injected
```
