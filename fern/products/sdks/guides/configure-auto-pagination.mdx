Fern's auto-pagination supports offset, cursor, URI, and path-based pagination schemes, providing SDK users with simple iterators to loop through all results instead of managing pagination complexity manually.

## Generated SDK behavior

<Tabs>
<Tab title="TypeScript">

Fern generates a method that returns a `Page<T>` implementing the `AsyncIterable` interface:

```typescript
const response = await client.plants.list();
for await (const plant of response) {
  console.log(plant);
}
```
</Tab>
<Tab title="Python">

Fern generates a method that returns a `Pager[T]` implementing the `Generator` interface:

```python
for plant in client.plants.list(page=1, page_size=10):
    print(plant)

# Async client
async for plant in await client.plants.list(page=1, page_size=10):
    print(plant)
```
</Tab>
</Tabs>

## Setting up auto-pagination

Annotate the desired endpoint with the pagination configuration, specify the pagination scheme (`offset`, `cursor`, `next_uri`, or `next_path`), and indicate where your results are located using dot-access notation.

<Tabs>
<Tab title="OpenAPI">
```yaml title="openapi.yml" {5-7}
paths:
  /plants:
    get:
      operationId: list_plants
      x-fern-pagination:
        cursor: $request.cursor
        next_cursor: $response.next
        results: $response.results
```
</Tab>
<Tab title="Fern Definition">
```yaml title="service.yml" {5-8}
service:
  endpoints:
    list:
      pagination:
        cursor: $request.starting_after
        next_cursor: $response.page.next.starting_after
        results: $response.data
```
</Tab>
</Tabs>
