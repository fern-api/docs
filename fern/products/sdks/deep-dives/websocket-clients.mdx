---
title: WebSocket clients
description: Generate typed WebSocket clients in your SDKs for bidirectional communication with connection management, typed messages, and automatic reconnection.
---

Fern generates typed WebSocket clients from your [channel definitions](/learn/api-definitions/ferndef/websockets). The generated clients handle connection management, typed send/receive messages, and automatic reconnection.

## Language support

| Language | Supported | Config flag | Notes |
|----------|-----------|-------------|-------|
| TypeScript | Yes | `generateWebSocketClients: true` | Reconnecting client with event handlers |
| Python | Yes | `should_generate_websocket_clients: true` | Sync and async context managers |
| Java | Yes | Enabled by default | — |
| C# | Yes | `experimental-enable-websockets: true` | — |
| Rust | Yes | `enableWebsockets: true` | — |
| Go | Types only | — | Generates types but no WebSocket client |
| Ruby | No | — | — |

## Enable WebSocket client generation

Add the config flag to the relevant generator in your `generators.yml`:

<CodeBlocks>
```yaml TypeScript
groups:
  ts-sdk:
    generators:
      - name: fernapi/fern-typescript-sdk
        version: ...
        config:
          generateWebSocketClients: true
```

```yaml Python
groups:
  python-sdk:
    generators:
      - name: fernapi/fern-python-sdk
        version: ...
        config:
          should_generate_websocket_clients: true
```

```yaml C#
groups:
  csharp-sdk:
    generators:
      - name: fernapi/fern-csharp-sdk
        version: ...
        config:
          experimental-enable-websockets: true
```

```yaml Rust
groups:
  rust-sdk:
    generators:
      - name: fernapi/fern-rust-sdk
        version: ...
        config:
          enableWebsockets: true
```
</CodeBlocks>

Java generates WebSocket clients by default with no additional configuration.

## Generated SDK behavior

Given a channel definition like:

```yaml title="realtime.yml"
channel:
  path: /realtime/{session_id}
  auth: true
  path-parameters:
    session_id: string
  query-parameters:
    model: optional<string>
  messages:
    send:
      origin: client
      body: SendEvent
    receive:
      origin: server
      body: ReceiveEvent
```

Fern generates the following client code:

<Tabs>
<Tab title="TypeScript" language="typescript">

The TypeScript SDK generates a `RealtimeSocket` class with typed `send` methods, event handlers, and a `ReconnectingWebSocket` that automatically retries dropped connections.

```typescript
const client = new MyClient({ token: "..." });

const socket = await client.realtime.createRealtimeConnection({
  sessionId: "session-123",
  model: "gpt-4",
});

socket.on("open", () => {
  console.log("Connected");
});

socket.on("message", (message) => {
  // message is typed as ReceiveEvent
  console.log(message.data);
});

socket.on("error", (error) => {
  console.error(error);
});

socket.sendSend({ text: "Hello" });

// Close when done
socket.close();
```

</Tab>
<Tab title="Python" language="python">

The Python SDK generates both sync (`contextmanager`) and async (`asynccontextmanager`) WebSocket clients.

**Sync:**
```python
with client.realtime.create_realtime_connection(
    session_id="session-123",
    model="gpt-4",
) as ws:
    ws.send_send(SendEvent(text="Hello"))
    response = ws.recv()  # typed as ReceiveEvent
    print(response)
```

**Async:**
```python
async with client.realtime.create_realtime_connection(
    session_id="session-123",
    model="gpt-4",
) as ws:
    await ws.send_send(SendEvent(text="Hello"))
    response = await ws.recv()
    print(response)
```

Both clients also support iteration and event-based listening:

```python
# Iteration
with client.realtime.create_realtime_connection(
    session_id="session-123",
) as ws:
    for message in ws:
        print(message)

# Event-based
with client.realtime.create_realtime_connection(
    session_id="session-123",
) as ws:
    ws.on("message", lambda msg: print(msg))
    ws.start_listening()
```

</Tab>
</Tabs>

## Defining WebSocket channels

WebSocket clients are generated from channel definitions in your Fern Definition. For the full syntax, including authentication, headers, path parameters, query parameters, and examples, see [WebSockets in the Fern Definition](/learn/api-definitions/ferndef/websockets).
