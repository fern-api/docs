---
title: SSE metadata access
description: Access server-sent event metadata (event ID, event type, retry interval) in Fern-generated SDKs for stream resumption and protocol-level control.
---

When your API uses [server-sent events](/learn/api-definitions/openapi/endpoints/sse#server-sent-events), the generated SDK returns a streaming response.

## Default iteration

By default, iterating the stream yields parsed data objects:

<CodeBlocks>
  <CodeBlock title="TypeScript">
    ```ts
    const stream = await client.plants.stream({ query: "fern" });

    for await (const data of stream) {
      console.log(data); // parsed response object
    }
    ```
  </CodeBlock>
  <CodeBlock title="Python">
    ```python
    response = client.plants.stream(query="fern")

    for data in response:
        print(data)  # parsed response object
    ```
  </CodeBlock>
  <CodeBlock title="Go">
    ```go
    stream := client.Plants.Stream(ctx, &PlantRequest{Query: "fern"})
    defer stream.Close()

    for {
      data, err := stream.Recv()
      if err != nil {
        break
      }
      fmt.Println(data) // parsed response object
    }
    ```
  </CodeBlock>
</CodeBlocks>

## Metadata-aware iteration

<Note>
Metadata-aware iteration is available for TypeScript and Go. Python SDKs support default iteration only.
</Note>

TypeScript and Go SDKs support metadata-aware iteration to read SSE protocol fields — event ID, event type, and retry interval — alongside the parsed data. Default iteration is unchanged, so opting in is fully backward compatible.

<CodeBlocks>
  <CodeBlock title="TypeScript">
    ```ts
    const stream = await client.plants.stream({ query: "fern" });

    for await (const event of stream.withMetadata()) {
      event.data   // parsed response object (same type as default iteration)
      event.id     // SSE event ID (string | undefined)
      event.event  // SSE event type (string | undefined)
      event.retry  // SSE retry interval in ms (number | undefined)
    }
    ```
  </CodeBlock>
  <CodeBlock title="Go">
    ```go
    stream := client.Plants.Stream(ctx, &PlantRequest{Query: "fern"})
    defer stream.Close()

    for {
      event, err := stream.RecvEvent()
      if err != nil {
        break
      }
      event.Data  // parsed response object (same type as Recv)
      event.ID    // SSE event ID (string)
      event.Event // SSE event type (string)
      event.Retry // SSE retry interval in ms (int)
    }

    // Read the most recent event ID without consuming the next event:
    lastID := stream.LastEventID()
    ```
  </CodeBlock>
</CodeBlocks>

<Note>
`withMetadata()` requires TypeScript SDK generator version 3.73.0+. `RecvEvent()` requires Go SDK generator version 1.32.0+.
</Note>

## Stream resumption

The event ID is useful for resuming a stream via the standard `Last-Event-ID` header: store the last received ID as you iterate, then pass it back to the server on reconnection. This requires server-side support for the `Last-Event-ID` header.
