---
title: Webhook signature verification
description: Configure webhook signature verification in your Fern-generated SDKs to validate HMAC or asymmetric signatures, protect against replay attacks, and ensure webhook authenticity.
---


When you define webhooks in your API spec, Fern automatically generates utilities that allow your SDK users to verify webhook signatures and ensure events originate from your API. These helpers are generated for the TypeScript, Python, Java, Go, PHP, Ruby, and C# SDKs.

Fern supports two signature verification methods:
- **Hash-based Message Authentication Code (HMAC)** — Symmetric key verification using shared secrets
- **Asymmetric** — Public key verification using RSA, Elliptic Curve Digital Signature Algorithm (ECDSA), or Ed25519 keys

## Generated SDK behavior

The generated SDK exposes a `verifyWebhookSignature` utility:

```typescript
import { verifyWebhookSignature } from "my-api";

// In your webhook handler
app.post("/webhooks", (req, res) => {
  // Verify the signature using your webhook secret
  const payload = verifyWebhookSignature(req, {
    secret: process.env.WEBHOOK_SECRET,
  });

  // Process the verified payload
  console.log("Received event:", payload);

  res.status(200).send("OK");
});
```

The example uses TypeScript; each other SDK exposes an equivalent helper.

## Body-hash binding

Some providers don't HMAC-sign the raw request body directly. Instead, they transmit a hash of the body as a query parameter on the notification URL (for example, Twilio's `bodySHA256`) and HMAC-sign the URL itself.

When a webhook declares a body-hash binding, the generated helper verifies in two steps and both must pass:

1. Recompute the hash of the raw body and timing-safe-compare it to the query parameter on the notification URL. A missing or mismatched hash fails verification.
2. Verify the HMAC signature over the verbatim notification URL.

The body-hash algorithm and encoding are independent of the outer HMAC's. Twilio, for example, uses a SHA-256 hex body hash with a SHA-1 base64 signature. Body-hash binding is derived from the API's webhook definition and activates automatically, with no additional configuration.

## Setting up webhook signature verification

Configure signature verification in your API definition. Settings can be applied at the **document level** (inherited by all webhooks) or **per-webhook** (overrides document-level settings).

The `payload-format` field controls which components (body, timestamp, message ID, notification URL) are included in the signed data. For asymmetric verification, include a `timestamp` component so the timestamp is cryptographically authenticated and replay protection is effective.

<Tabs>
<Tab title="HMAC">
```yaml title="openapi.yml"
x-fern-webhook-signature:
  type: hmac
  header: x-webhook-signature
  algorithm: sha256
  encoding: hex
  payload-format:
    components: [timestamp, body]
    delimiter: "."
  timestamp:
    header: x-webhook-timestamp
    format: unix-seconds
    tolerance: 300
```
</Tab>
<Tab title="Asymmetric">
```yaml title="openapi.yml"
x-fern-webhook-signature:
  type: asymmetric
  header: x-webhook-signature
  asymmetric-algorithm: ecdsa-sha256
  encoding: base64
  payload-format:
    components: [timestamp, body]
    delimiter: "."
  timestamp:
    header: x-webhook-timestamp
    format: unix-seconds
    tolerance: 300
```
</Tab>
</Tabs>
