## 4.26.0
**`(feat):`** SDK variables that declare an environment variable fallback (`env` in `api.yml` or `x-fern-env` on
`x-fern-sdk-variables`) now default to `System.getenv(...)` in the client builder, and `build()`
throws an `IllegalStateException` with a clear message when neither the builder method nor the
environment variable provides a value, instead of rendering `null` into request paths. The check
lives in the generated `setVariables(builder)` hook, so overriding it to supply the value still works.


## 4.25.0
**`(feat):`** Wire tests now cover error responses and every example, not just the first example's happy path.
Each endpoint gets one test per user-specified example. When none of an endpoint's user examples
is an error, the autogenerated error examples are added too. Error tests assert that the call throws
the typed error class (or the base API exception when the status code isn't declared) and check the
status code and error body. Success responses use the endpoint's declared status code instead of
always returning 200, and the test client is built with `maxRetries(0)`.
Set `wire-tests-fallback-to-autogenerated-error-examples: false` to leave out autogenerated error examples.


**`(fix):`** Wire tests now compile when the API has a type named `Test` or `Exception`. The test annotation
and `throws` clause use fully qualified names in that case, so they no longer clash with the imported API type.
