## 4.37.0
**`(feat):`** Add `retryDelays(List<Duration>)` to `ClientOptions.Builder` and the generated root client builders (sync, async
and multi-auth stages) for an explicit retry schedule: the n-th retry waits for the n-th duration and the request
stops retrying once the list is exhausted, so the list size replaces `maxRetries` and the exponential backoff
settings. Delays are used as-is (no jitter); `Retry-After` / `X-RateLimit-Reset` headers still take precedence
for that attempt. Default behaviour is unchanged.


## 4.36.0
**`(feat):`** Add `retryOnStatusCodes(Set<Integer>)` to `ClientOptions.Builder` and the generated root client builders
(sync, async and multi-auth stages). It replaces the default set of HTTP status codes that trigger an automatic
retry (408, 429 and 5xx), so a consumer can retry only `429`, or `429` and `503`, and have other 5xx responses
returned as-is. The default is unchanged; `maxRetries`, the backoff settings and Retry-After handling are
unaffected.
