## 3.108.0
**`(fix):`** With `noSerdeLayer: false`, JSON-style parts of a multipart request are now serialized before they are
encoded, as JSON request bodies are. A part whose type is or contains a named type was sent as `toJson(value)`
with the SDK's camelCase property names instead of the wire names.


**`(feat):`** Add the opt-in `includeMultipartPartContentType` config option. When enabled, non-file parts of a
multipart request carry their declared content type (e.g. OpenAPI
`encoding.<part>.contentType: application/json`) as the part's `Content-Type` header. It is off by
default because in browsers such parts are sent as a Blob, which also adds `filename=""`.


## 3.107.8
**`(fix):`** With `noSerdeLayer: false`, the serialization `Raw` type of an undiscriminated union with a
self-recursive map member (e.g. `map<string, JsonLike>`) now uses an index signature instead of
`Record<string, JsonLike.Raw>`, which TypeScript rejected as a circular type alias (TS2456).


**`(fix):`** A named alias of a string-keyed map (e.g. `Branch = map<string, Node>`) is now emitted as
`{ [key: string]: Node }` instead of `Record<string, Node>`, in both the public type and the
serialization `Raw` type. The two are the same type, but TypeScript rejects a cycle that runs through
`Record` as a circular type alias (TS2456), so a map schema that is part of a recursive type now compiles.
