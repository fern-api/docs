## 3.107.6
**`(fix):`** TypeScript dynamic snippets now follow the SDK generator's `noSerdeLayer` default (on unless `noSerdeLayer: false` or `serdeLayer: true` is set), so they use wire property names (e.g. `per_page`) that match the generated request types. Without a serde layer, query parameters, headers, file fields and object properties use the wire value, as the SDK does, even when a name override gives them a different original name. Property names that aren't valid identifiers (e.g. `org.iso.18013.5.1`) are now quoted, file values are always sent as a `Blob`, and a required file field (or file list) missing from the example gets a `fs.createReadStream("/path/to/your/file")` placeholder instead of being dropped. Optional file fields missing from the example are still left out; dynamic IR from CLIs that predate the `isOptional` flag treats every file as required. A config that never sets `noSerdeLayer` but pins a TypeScript generator older than 1.0 (where the serde layer was on by default) now gets wire-name snippets; `fern generator upgrade` sets the flag explicitly, so upgraded configs are unaffected.


## 3.107.5
**`(fix):`** XML (TwiML) serialization drops characters outside the XML 1.0 `Char` production (e.g. `\x01`) from text and attribute values instead of emitting XML that no parser accepts.


## 3.107.4
**`(fix):`** XML (TwiML) child builder methods accept the element's text content as a string, so legacy-style calls
such as `response.dial("+15551234567")` and `response.say("hi")` produce `<Dial>+15551234567</Dial>`
instead of an empty element. Element text no longer escapes double quotes as `&quot;` (attributes still do),
matching the legacy TwiML output.
