## 3.108.4
**`(fix):`** In Node, a rejected WebSocket handshake (a non-101 response) now includes the server's response
body in the error. Callers see `Unexpected server response: 400 (<body>)` instead of only
`Unexpected server response: 400`, so a bad query parameter or an auth failure can be told
apart from other errors. The `ErrorEvent` also exposes the rejection as optional `statusCode`,
`headers` and `body` fields (the body is capped at 1000 characters); they stay `undefined` for
other errors. The error reaches `error` listeners and `waitForOpen()`. Retry behavior does not
change, and browser WebSockets are unaffected.


## 3.108.3
**`(fix):`** The generated serialization layer no longer throws "Maximum call stack size exceeded" when a
value fails validation with a very large number of nested errors. `list`, `object` and `record`
schemas now append child errors in a loop instead of spreading them into `Array.prototype.push`.
