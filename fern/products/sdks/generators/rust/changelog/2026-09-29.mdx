## 0.49.1
**`(chore):`** Bump bundled @fern-api/generator-cli to 0.10.3. When the hosted auto-version analysis of the
full SDK diff fails, generator-cli now retries chunk-by-chunk instead of silently applying a
PATCH bump; any remaining unavailable or incomplete analysis adds a "Version bump not verified"
notice to the SDK PR body and disables automerge.


## 0.49.0
**`(feat):`** Every multi-URL environment now embeds its URLs: `impl Default for <Env>Urls` per
environment and a constructor per environment (`Environment::staging()`), so selecting a
non-default environment no longer means retyping URLs from `generators.yml`. The README
environments snippet of a multi-URL SDK sets `environment` through that constructor instead
of `Environment::Production.url()`, which does not compile against a tuple variant.


**`(fix):`** In a multi-URL environment an explicit `base_url` now wins over the default environment.
`ClientConfig::default()` set both `base_url` and `environment`, and every endpoint let the
environment win, so `ClientConfig { base_url: "https://sandbox…", ..Default::default() }`
silently sent every request to the default (production) environment. Requests now go to
`base_url` whenever it is anything other than one of the configured environment's URLs (or
the default environment's URL that `Default` fills in); otherwise each request goes to the
environment's URL for its service, as before. `ClientConfig::service_url` carries the rule.
