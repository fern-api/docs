## 1.33.0
**`(feat):`** The generated `WebhooksHelper` HMAC verifier now accepts a per-call algorithm override via an optional `algorithm` parameter on `verifySignature`,
one of `sha1`, `sha256`, `sha384` or `sha512`. When omitted, the algorithm configured in
`webhook-signature` is used, so existing callers are unchanged. This lets one endpoint verify both
legacy HMAC-SHA1 (auth-token) and HMAC-SHA256 (shared-key) signed webhooks.
The verifier also logs a warning distinguishing an early failure (missing signature header) from a
failed verification (signature mismatch); it still returns `false` and never throws.


## 1.32.0
**`(feat):`** XML (TwiML) types keep text segments, typed child models and raw `Element` children in a single
ordered `content` list, so `to_xml` emits them in the order they were added
(`response.say("a"); response.add_child(Element.new("Custom")); response.say("b")` yields
`<Say>a</Say><Custom/><Say>b</Say>`) and `from_xml` preserves document order, including the
position of unknown elements. Adds `add_text(String)` to XML types and `Element` for mixed content
such as `<Say>Hi <break strength="weak"/> world</Say>`. Typed child properties and additional
children remain available and are reconciled into the content order on serialization.


## 1.31.1
**`(fix):`** XML-encoded (TwiML) types now include the `<?xml version="1.0" encoding="UTF-8"?>`
declaration by default when serialized to XML; pass the declaration flag as `false`
to omit it. Nested child elements and raw `XmlElement`s are still written without it.


## 1.31.0
**`(feat):`** Add support for SDK variables (`x-fern-sdk-variables` / `variables` in `api.yml`).
Each variable is exposed as an optional keyword on the root client (e.g.
`Client.new(target_account_sid: "AC...")`); path parameters bound to a variable are
removed from the endpoint methods and request classes, and the value is read from
the client instead. String variables declared with an `env` fall back to
`ENV.fetch("<ENV_VAR>", nil)` when the keyword is omitted, and endpoints raise an
`ArgumentError` with a clear message when a required variable is still unset.
