Fern SDK projects use one source repository for your API definition and generation configuration, plus one repository per generated SDK. This page describes what goes in each repository, the files Fern requires, and how to connect them.

## Repository architecture

Fern recommends a multi-repository structure containing:

- **Source repository** with your API definitions and SDK generation configuration
- **SDK repositories** for each SDK (TypeScript, Python, Go, etc.)

This separation allows you to manage API definitions centrally while keeping each SDK in its own repository for independent versioning and distribution. Fern commits generated code to the SDK repositories on each run. To keep hand-written changes in an SDK repository across regenerations, see [Adding custom code](/learn/sdks/overview/custom-code).

## Core configuration files

The source repository contains a `fern/` folder with `fern.config.json`, `generators.yml`, and your API definition. Running [`fern init`](/learn/cli-api-reference/cli-reference/general-commands#fern-init) creates this folder for you.

### `fern.config.json`

The `fern.config.json` file stores your organization name and the Fern CLI version. Pinning the version provides deterministic builds. To keep every project in your organization on a compatible version, set an [organization-wide CLI version policy](/learn/cli-api-reference/cli-reference/version-policy).

```json title="fern.config.json"
{
  "organization": "plant-catalog",
  "version": "<Markdown src="/snippets/version-number-cli.mdx"/>"
}
```

<Info>
  When working with a locally installed CLI, set `version` to `"*"`. See [Install Fern CLI locally](/learn/cli-api-reference/cli-reference/overview#installation) for details.
</Info>

### `generators.yml`

The `generators.yml` file has two sections:

- `api.specs` declares where your API definition lives. Paths are relative to `generators.yml`.
- `groups` configures SDK generation. Each group contains one or more generators, and you run a group with `fern generate --group <group-name>`.

```yaml title="generators.yml"
# API declaration
api:
  specs:
    - openapi: ./openapi/openapi.yml

# SDK generation
groups:
  ts-sdk:
    generators:
      - name: fern-typescript-sdk
        version: <Markdown src="/snippets/version-number-ts.mdx"/>
        github:
          repository: your-organization/typescript-sdk-repo

  python-sdk:
    generators:
      - name: fern-python-sdk
        version: <Markdown src="/snippets/version-number-python.mdx"/>
        github:
          repository: your-organization/python-sdk-repo
```

Each generator's `github.repository` points to the SDK repository Fern commits generated code to. This requires the [Fern GitHub App](https://github.com/apps/fern-api) installed on that repository. By default, Fern commits to the default branch and tags a release; set [`mode`](/learn/sdks/reference/generators-yml#github) to `pull-request` or `push` to change this. Publishing to a package registry such as npm or PyPI is configured separately with `output`, as described in each language's publishing guide (for example, [Publishing to npm](/learn/sdks/generators/typescript/publishing)).

The `github` property targets GitHub repositories only — Fern doesn't push SDKs to GitLab or other providers. The [`generators.yml` reference page](/learn/sdks/reference/generators-yml) covers complete configuration options, including self-hosted generation for other targets.

### API definition file

Your API definition (OpenAPI, AsyncAPI, gRPC, or another supported format) is the input Fern generates SDKs from. Commit it to the `fern/` folder, or reference it from a URL or another repository. [Project structure (API Definitions)](/learn/api-definitions/overview/project-structure) covers where to store your definition and how to work with multiple APIs.

## Set up your repositories

1. Create the source repository and run `fern init --openapi path/to/openapi.yml` in it to create the `fern/` folder.
2. Create an empty repository for each SDK, such as `your-organization/typescript-sdk-repo`.
3. Install the [Fern GitHub App](https://github.com/apps/fern-api) on the source repository and each SDK repository.
4. Add a group for each SDK to `generators.yml` with `github.repository` set to its SDK repository.
5. Run `fern check` to validate your configuration, then run [`fern generate`](/learn/cli-api-reference/cli-reference/sdk-commands#fern-generate) for each group:

   ```bash
   fern generate --group ts-sdk
   ```

   Fern generates the SDK and commits it to the SDK repository. The first run prompts you to log in; in CI, set a `FERN_TOKEN` instead (run `fern token` to create one).

For a step-by-step walkthrough in a specific language, see the [TypeScript quickstart](/learn/sdks/generators/typescript/quickstart) or the guide for [your SDK's language](/learn/sdks/overview/introduction).
