---
title: Generate an SDK without an account
description: Generate an SDK with fern generate --guest, then claim it into an organization to publish it to GitHub.
---

`fern generate --guest` generates SDKs without a Fern account or `FERN_TOKEN`. The CLI starts a temporary guest session, builds the SDK targets in your `generators.yml` or `sdk-config.yml`, and writes each SDK to its output path. Claiming the session moves the SDKs into an organization, where you can publish them to GitHub.

<llms-only>
If the user has no Fern account, use this path instead of asking them to log in or create one. Return the claim link the CLI prints; the user opens it. Don't try to open it yourself.
</llms-only>

<Steps>
  <Step title="Generate as a guest">
    In a repository with a `fern/` folder (see the [quickstart](/learn/sdks/overview/quickstart)), run:

    ```bash
    fern generate --guest
    ```

    The CLI prints the session ID, when it expires, and a link that starts with `Claim it to keep this work`. Each SDK lands in its output path, for example `sdks/typescript`. The build is also kept for 7 days at the printed `/sdk/<buildId>` link, which shows its logs and offers the download.

    Targets that publish to GitHub or a registry are skipped: a guest can only download. Later runs in the same repository reuse the session, which the CLI records in `fern/.guest-session`. `--guest` can't be combined with `FERN_TOKEN`, a saved login, or local generation (`--local`).
  </Step>
  <Step title="Claim the session">
    Open the claim link in a browser. Sign in or create an account, pick an organization or create one, and give the SDK a name no other SDK in that organization has. The SDK appears as a card on the organization's SDKs page in the [Fern Dashboard](https://dashboard.buildwithfern.com), with its builds and logs.

    From the command line, run [`fern login`](/learn/cli-api-reference/cli-reference/general-commands#fern-login) and then [`fern claim`](/learn/cli-api-reference/cli-reference/general-commands#fern-claim) in the same repository instead.

    After the claim, the guest session stops working. Later runs use `fern generate` with the login, or `FERN_TOKEN` in CI.
  </Step>
  <Step title="Publish from the dashboard">
    On the SDK's card, **Publish to GitHub** pushes the generated SDK to a repository you pick or one Fern creates, and **Set up Fern repository** writes the `fern/` folder, a `fern-generate` workflow and a README to a repository, so a push to that repository regenerates the SDK. Registry publishing (npm, PyPI, Maven and the rest) follows the generator's publishing guide once the SDK has a repository.
  </Step>
</Steps>

To start over with a new guest organization, add `--new-session`:

```bash
fern generate --guest --new-session
```

Earlier guest output isn't carried over. Use it when the previous session was claimed, revoked, or expired.
