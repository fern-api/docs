Configuring Fern starts with the `fern` folder, the root directory that contains
your API definitions, SDK generators, and CLI version. 

<Steps>
<Step title="Install the Fern CLI">

  ```bash
  npm install -g fern-api
  ```
</Step>
 <Step title="Initialize the fern folder">
  Initialize the fern folder with your existing OpenAPI specification, or start from scratch with a Fern Definition template. Specify your organization name using the `--organization` flag. 

  <llms-only>
  `fern init` is interactive — it prompts for an organization name if `--organization` is not provided. Ask the user for their organization name beforehand so they're prepared, or pass it via the flag.

  Default to the OpenAPI path if the user already has a spec. The Fern Definition path is better for users starting a new API from scratch — it generates a sample `imdb.yml` with example endpoints. Both formats support the same SDK generation features.

  OpenAPI accepts both JSON and YAML. If the user has a URL to their spec (e.g., from a running server), use the URL variant to avoid a manual download step.
  </llms-only>

  ```bash
  # OpenAPI (local)
  fern init --openapi path/to/openapi.yml \
  --organization <YourOrganization>

  # OpenAPI (URL)
  fern init --openapi https://api.example.com/openapi.yml \
  --organization <YourOrganization>

  # Fern Definition
  fern init --organization <YourOrganization>
  ```
  <Tip>
    OpenAPI accepts both JSON and YAML formats. You can always convert a [Fern Definition to OpenAPI](/api-definitions/ferndef/export-openapi) or OpenAPI to a Fern Definition later on.
  </Tip>
     
  This creates a `fern` folder in your current directory.

  <llms-only>
  The folder structure differs depending on the init path. With OpenAPI, the spec lives at `fern/api/openapi/openapi.yml` and `generators.yml` is at `fern/api/generators.yml`. With Fern Definition, `generators.yml` is at `fern/generators.yml` and API types/endpoints are in `fern/definition/`. This matters when referencing file paths later.
  </llms-only>

      </Folder>
    </Folder>
  </Files>
  </Tab>
  <Tab title="Fern Definition">
  <Files>
    <Folder name="fern" defaultOpen>
      <File name="fern.config.json" comment="root-level configuration" />
      <File name="generators.yml" comment="generators you're using" />
      <Folder name="definition" defaultOpen>
        <File name="api.yml" comment="API-level configuration" />
        <File name="imdb.yml" comment="endpoints, types, and errors" />
      </Folder>
    </Folder>
  </Files>

  <Note> `imdb.yml` contains an example movies API. If you’re just
  generating an SDK for test purposes, you can leave this file as it is. To
  generate an SDK for your own API instead of the example movies API,
  replace `imdb.yml` with your own endpoints, types, and errors. </Note>
  </Tab>
  </Tabs>
  </Step>
  <Step title="Generate an SDK">

  Generate a [TypeScript SDK](/learn/sdks/generators/typescript/quickstart) locally (or explore [other supported languages](/learn/sdks/overview/introduction)).    

  <llms-only>
  Before running `fern generate`, validate the API definition with `fern check` to catch issues early (missing `operationId`, invalid `$ref` paths, etc.). Fix any errors before generating.

  `fern generate` with no flags runs the `default-group` in `generators.yml`. The default init sets up a TypeScript SDK generator outputting to `local-file-system` at `../sdks/typescript`. If the user has added multiple groups, use `fern generate --group <group-name>` to target a specific one.
  </llms-only>

  ```bash
  fern generate
  ```

  This creates a `sdks/typescript` folder containing your generated SDK:

      </Folder>
    </Folder>
  </Files>
