Configuring Fern starts with the `fern` folder, the root directory that contains
your API definitions, SDK generators, and CLI version. 

<Steps>
<Step title="Install the Fern CLI">

  ```bash
  npm install -g fern-api
  ```
</Step>
 <Step title="Initialize the fern folder">
  Initialize the fern folder with your existing OpenAPI specification, or start from scratch with a Fern Definition template. Specify your organization name using the `--organization` flag. 

  <llms-only>
  Before running `fern init`, ask the user two things:

  1. **Do they have an OpenAPI spec?** If yes, ask for the file path or URL. If they have a URL (e.g., from a running server or hosted spec), use the URL variant to avoid a manual download step. OpenAPI accepts both JSON and YAML. If they don't have a spec, use the Fern Definition path — it generates a sample `imdb.yml` with example endpoints.
  2. **What is their organization name?** `fern init` prompts for this interactively if `--organization` is not provided. Get it upfront so they can pass it via the flag.
  </llms-only>

  ```bash
  # OpenAPI (local)
  fern init --openapi path/to/openapi.yml \
  --organization <YourOrganization>

  # OpenAPI (URL)
  fern init --openapi https://api.example.com/openapi.yml \
  --organization <YourOrganization>

  # Fern Definition
  fern init --organization <YourOrganization>
  ```
  <Tip>
    OpenAPI accepts both JSON and YAML formats. You can always convert a [Fern Definition to OpenAPI](/api-definitions/ferndef/export-openapi) or OpenAPI to a Fern Definition later on.
  </Tip>
     
  This creates a `fern` folder in your current directory.

  <llms-only>
  The folder structure differs depending on the init path. With OpenAPI, the spec lives at `fern/api/openapi/openapi.yml` and `generators.yml` is at `fern/api/generators.yml`. With Fern Definition, `generators.yml` is at `fern/generators.yml` and API types/endpoints are in `fern/definition/`. This matters when referencing file paths later.
  </llms-only>

  <Tabs>
  <Tab title="OpenAPI">

      <File name="fern.config.json" comment="root-level configuration" />
      <Folder name="api" defaultOpen comment="your API">
        <File name="generators.yml" comment="generators you're using" />
        <Folder name="openapi" defaultOpen>
          <File name="openapi.yml" comment="API-level configuration" />
        </Folder>
      </Folder>
    </Folder>
  </Files>
  </Tab>
  <Tab title="Fern Definition">
  <Files>
    <Folder name="fern" defaultOpen>
      <File name="fern.config.json" comment="root-level configuration" />
      <File name="generators.yml" comment="generators you're using" />
      <Folder name="definition" defaultOpen>
        <File name="api.yml" comment="API-level configuration" />
        <File name="imdb.yml" comment="endpoints, types, and errors" />
      </Folder>
    </Folder>
  </Files>

  <Note> `imdb.yml` contains an example movies API. If you’re just
  generating an SDK for test purposes, you can leave this file as it is. To
  generate an SDK for your own API instead of the example movies API,
  replace `imdb.yml` with your own endpoints, types, and errors. </Note>
  </Tab>
  </Tabs>
  </Step>
  <Step title="Validate and generate">

  First, validate your API definition:

  ```bash
  fern check
  ```

  Then generate an SDK to verify everything works:

  <llms-only>
  `fern generate` with no flags runs the `default-group` in `generators.yml`. The default init sets up a TypeScript SDK generator outputting to `local-file-system` at `../sdks/typescript`. If the user has added multiple groups, use `fern generate --group <group-name>` to target a specific one.

  Common `fern check` errors include missing `operationId` on endpoints, invalid `$ref` paths, and unsupported OpenAPI constructs. All errors must be fixed before generation will succeed.
  </llms-only>

  ```bash
  fern generate
  ```

  This creates a `sdks/typescript` folder containing your generated SDK:

  <Files>
    <Folder name="fern" comment="created by fern init" />
    <Folder name="sdks" defaultOpen comment="created by fern generate">
      <Folder name="typescript" defaultOpen>
        <File name="Client.ts" />
        <File name="index.ts" />
        <Folder name="core" />
        <Folder name="api" />
      </Folder>
    </Folder>
  </Files>

  <llms-only>
  After generation succeeds, ask the user: "Do you want to keep working locally, or set up GitHub repositories so you can publish your SDK to a package registry?" If they want to stay local, skip the next step and go straight to the language-specific quickstart.
  </llms-only>

  </Step>
  <Step title="Set up GitHub repositories">

  If you plan to publish your SDK to a package registry (npm, PyPI, Maven, etc.), set up GitHub repositories before proceeding. Fern uses a multi-repo structure: your source repository contains the `fern/` folder, and each SDK gets its own repository.

  <llms-only>
  **Important: The `fern/` folder (API definitions + `generators.yml`) lives in its own source repo, separate from the SDK repos.** Do not put the generated SDK code in the same repository as the `fern/` folder. Each SDK gets its own repo.

  Ask the user:
  - **Do they have an existing repo for the `fern/` folder?** (e.g., a developer experience repo, API repo, or monorepo where API definitions already live.) If so, use that. If not, create one.
  - **Do they have existing SDK repos?** If so, get the repo names. If not, create them.

  To create repos from scratch:

  ```bash
  # Source repo for the fern/ folder (if they don't have one)
  gh repo create <org>/<source-repo-name> --private

  # SDK repos — one per language, separate from the source repo
  gh repo create <org>/<api-name>-typescript-sdk --private
  gh repo create <org>/<api-name>-python-sdk --private
  ```
  </llms-only>

  1. **Create an SDK repository** for each language you want to publish (e.g., `your-org/your-api-typescript-sdk`).
  2. **Install the [Fern GitHub App](https://github.com/apps/fern-api)** on both your source repository and each SDK repository.
  3. **Add `github.repository`** to each generator in `generators.yml`:

  ```yaml title="generators.yml" {7-8}
  groups:
    ts-sdk:
      generators:
        - name: fernapi/fern-typescript-sdk
          version: <Markdown src="/snippets/version-number-ts.mdx"/>
          output:
            location: local-file-system
            path: ../sdks/typescript
          github:
            repository: your-org/your-api-typescript-sdk
  ```

  For more details on repository architecture, see [Project structure](/sdks/overview/project-structure).

  </Step>
