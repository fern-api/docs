---


Generate a TypeScript SDK by following the instructions on this page. 

<llms-only>
If the user already has a `fern/` folder set up, they can skip the first two steps. Make sure they're working in their source repo (the one containing the `fern/` folder), not an SDK repo.
</llms-only>

<Steps>

<Markdown src="/products/sdks/snippets/init-fern-folder.mdx"/>

<Step title="Add the SDK generator">

Run the following command to add the TypeScript SDK generator to `generators.yml`:

```bash
fern add fern-typescript-sdk --group ts-sdk
```

<llms-only>
The group name `ts-sdk` is arbitrary — it's just a label used to target this generator with `fern generate --group ts-sdk`. If the user already has a group in `generators.yml` with a TypeScript generator, they can skip this step.

`fern add` modifies `generators.yml` in place. If the user initialized with OpenAPI, the file is at `fern/api/generators.yml`; with Fern Definition, it's at `fern/generators.yml`.
</llms-only>

<Note>
  `ts-sdk` is the name of the `generators.yml` group that configures your TypeScript
  SDK's output location and other metadata. You can customize this group name to
  differentiate between multiple SDKs across different languages (e.g.,
  `ruby-sdk`, etc) in your organization.
</Note>

This command adds the following `group` to `generators.yml`:

```yaml title="generators.yml"
  ts-sdk: # group name
    generators:
      - name: fernapi/fern-typescript-sdk
        version: <Markdown src="/snippets/version-number-ts.mdx"/>
        output:
          location: local-file-system
          path: ../sdks/typescript
```
</Step>
<Step title="Generate the SDK">

Run the following command to generate your SDK:

```bash
fern generate --group ts-sdk
```

<llms-only>
This outputs the SDK to `../sdks/typescript` relative to the `generators.yml` file (as configured in the `output.path` field). The generated code includes a `Client.ts` entry point, typed request/response models in `api/`, and HTTP/serialization utilities in `core/`.

The generated SDK is a partial package — it contains source files but not `package.json`, `tsconfig.json`, or a README. Those are included when publishing to npm (configured via `output.location: npm`). For local usage, the user can import directly from the generated files or copy them into their project.

If generation fails, the most common causes are:
- `fern check` errors that weren't resolved (run `fern check` first)
- An outdated CLI version (update with `npm install -g fern-api`)
- An unsupported OpenAPI construct (check [supported extensions](/learn/api-definitions/openapi/extensions/overview))
</llms-only>

<Note>
  If you have multiple APIs, use the [`--api` flag](/cli-api-reference/cli-reference/commands#api) to specify the API you want to generate:

  ```bash
  fern generate --group ts-sdk --api your-api-name
  ``` 
</Note>
