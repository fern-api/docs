Fern supports several authentication methods to control access to customer documentation. Choose the method that best fits the customer's needs.

## Auth types

| Type | Use case | Configuration location |
|------|----------|----------------------|
| [JWT Authentication](/learn/sales-engineering/customer-setup/authentication/jwt-auth) | API key injection for customers | Vercel Edge Config (`api-key-injection`) |
| [API Key Injection for Demos](/learn/sales-engineering/customer-setup/authentication/demo-auth) | Demo environments with pre-loaded API keys | Vercel Edge Config (`api-key-injection` + `api-key-injection-demo`) |
| [RBAC](/learn/sales-engineering/customer-setup/authentication/rbac) | Role-based access control for customer docs | Vercel Edge Config (`authentication`) |
| [SSO with WorkOS](/learn/sales-engineering/customer-setup/authentication/workos-sso) | Single sign-on via enterprise identity providers | WorkOS + Vercel Edge Config |
| [Password Protection](/learn/sales-engineering/customer-setup/authentication/password-protection) | Simple global password for all docs | Vercel Edge Config |

## Setting up simple auth

For cases where all docs are behind auth (no RBAC, no SSO — just a single auth gate), refer to the [Slack thread on simple auth setup](https://buildwithfern.slack.com/archives/C095B8CQ8Q0/p1762376422438709).

## Common patterns

All authentication configurations are managed through Vercel Edge Config stores:
- Navigate to [Vercel Edge Config stores](https://vercel.com/buildwithfern/~/stores)
- Find the `fern-docs-config` store
- Add or update the relevant key for the customer's domain

After making changes, the customer may need to wait up to 15 minutes for edge config propagation, or trigger a manual revalidation by visiting:
```
https://{customer-domain}/api/fern-docs/revalidate
```
