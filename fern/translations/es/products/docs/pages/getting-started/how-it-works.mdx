---
title: "Cómo funciona Fern Docs"
description: "Aprende cómo Fern transforma tus especificaciones de API y documentación en una experiencia unificada para desarrolladores."
---

Fern combina tus especificaciones de API, archivos Markdown estáticos (como guías y tutoriales), activos multimedia (imágenes, vídeos, etc.) y configuraciones personalizadas definidas en tu archivo `docs.yml` para generar un sitio de documentación interactivo y alojado.

Este proceso se basa en dos flujos de trabajo principales: **editar** y **desplegar** tu documentación.

## Flujos de trabajo de contenido

Puedes actualizar tu documentación de dos maneras:

- **Edición directa**: Abre un pull request directamente en el repositorio de GitHub que contiene tu documentación (incluyendo tu configuración `docs.yml` y archivos Markdown).
- **Editor de Fern**: Usa el Editor de Fern para modificar tu documentación sin tocar código. La aplicación GitHub de Fern obtiene el estado actual de tu repositorio de documentación y lo pasa al Editor de Fern. Cuando envías cambios, la aplicación GitHub de Fern abre automáticamente un pull request para revisión.

Después de que la actualización pase por tu proceso de revisión, un aprobador puede fusionarla.

Puedes usar el Panel de Fern para gestionar la conexión con tu repositorio de GitHub, los miembros de la organización, los dominios y la versión de la CLI de Fern.

## Flujos de trabajo de despliegue

Cuando se fusiona un pull request en tu repositorio de documentación, un pipeline automatizado transforma tu contenido en un sitio de documentación en vivo en tres etapas principales:

### 1. Activar GitHub Action y obtener especificaciones de API

El PR fusionado activa una GitHub Action de Fern. La acción recupera tu especificación de API desde un repositorio separado usando autenticación con token seguro.

### 2. Generar y procesar contenido

La CLI de Fern ejecuta `fern generate --docs` para combinar tus especificaciones de API con el contenido de la documentación. Este proceso incluye:

- **Procesamiento de entradas**: El sistema combina tus archivos de especificación de API, el archivo de configuración `docs.yml`, los archivos `.mdx` y el contenido multimedia.
- **Infraestructura central**: El proceso de generación se ejecuta en la infraestructura AWS VPC de Fern, donde el microservicio de Fern Docs actúa como orquestador central.
- **Indexación de contenido**: Durante la generación, Fern indexa automáticamente el contenido de tu documentación para habilitar la funcionalidad de búsqueda en todo el sitio.

### 3. Desplegar en la plataforma de alojamiento

El contenido procesado se despliega en Vercel como un sitio de documentación con un Explorador de API integrado que permite a los usuarios probar los endpoints directamente dentro de la documentación.
