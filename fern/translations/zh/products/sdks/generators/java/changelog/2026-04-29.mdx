## 4.6.3
**`(fix):`** 修复在设置 `coerce-optional-schemas-to-nullable: true` 时，针对 `allow-multiple` 查询参数的 Java SDK 代码片段和线路测试生成。此前，包装在 `optional<...>` 和/或 `nullable<...>` 中的列表项会产生类似 `.strategy(Arrays.asList(Optional.of(...)))` 的调用，由于生成的构建器只暴露 `List<T>` 重载（没有 `List<Optional<T>>` 或 `List<Nullable<T>>`），因此无法编译。代码片段生成器现在会从列表项中剥离 `optional` 和 `nullable` 包装器，使发出的代码与现有构建器签名匹配。
