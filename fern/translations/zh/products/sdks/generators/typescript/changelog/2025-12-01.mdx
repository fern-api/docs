## 3.35.5
**`(fix):`** 修复 WebSocket 客户端，仅在通道具有 `auth: true` 时生成认证代码。
此前，只要 API 定义了认证方案就会生成认证代码，即使 WebSocket 通道不需要认证。
这导致客户端使用 `NormalizedClientOptions` 但连接方法试图访问 `authProvider` 的不匹配。


## 3.35.4
**`(fix):`** 将非状态码错误处理集中到生成的 SDK 中的单个可重用函数。
这将减少重复代码量，并使在所有端点之间维护一致的错误处理变得更容易。


## 3.35.3
**`(fix):`** 修复 WebSocket 客户端 `ConnectArgs` 接口以正确处理 `allow-multiple: true` 查询参数。
此前，具有 `allow-multiple: true` 的查询参数被类型化为 `T | undefined` 而不是 `T | T[] | undefined`。


## 3.35.2
**`(chore):`** * 在生成的 ci.yml 工作流的 pnpm 和 yarn install 命令中添加 --frozen-lockfile 标志。
* 在生成的 ci.yml 工作流中将 actions/checkout 更新到 v6，actions/setup-node 更新到 v6。


## 3.35.1
**`(fix):`** 修复对于非有效 JavaScript 标识符的属性名称（例如 `language-code`）的 WebSocket 查询参数解构。
生成的代码现在在解构中正确使用重命名语法（例如 `const { "language-code": languageCode } = args;`）。
