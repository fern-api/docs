## 3.43.0
**`(feat):`** 通过新的 `endpoint-security` 认证要求类型添加端点级安全配置支持。这允许 API 为每个端点指定不同的身份验证方案，实现对哪些端点接受哪些认证方法的细粒度控制（例如，某些端点使用 Bearer，其他端点使用 API Key）。


**`(feat):`** 添加 `RoutingAuthProvider`，根据端点元数据动态路由身份验证请求。当配置 `auth: endpoint-security` 时，SDK 使用端点元数据来确定每个请求使用哪个认证提供者。`AnyAuthProvider` 仍然是 `auth: any` 配置的默认选择。


**`(chore):`** 重构所有认证提供者以使用具有静态 `createInstance` 方法的工厂模式。这实现了类型安全的提供者实例化，基于可用凭据的条件提供者创建，以及具有特定方案上下文的更好错误消息。


**`(feat):`** 为认证选项添加条件包装器属性，以防止配置多个认证方案时的命名冲突（例如，`options.bearer.token` vs `options.oauth.token`）。


**`(chore):`** 在 `EndpointSupplier.get()` 中使 `endpointMetadata` 参数可选，以允许认证提供者在保持向后兼容性的同时优雅地处理没有元数据的端点。
