## 3.57.2
**`(fix):`** 修复带有未知/任意值类型的映射类型不包含多余的 `| undefined`。
之前，`map<string, UnknownType>` 生成 `Record<string, UnknownType | undefined>`
而不是 `Record<string, UnknownType>`。现在已正确从映射值类型中省略 `| undefined`。


## 3.57.1
**`(fix):`** 修复当 SDK 环境是对象（例如 `{ base: string; production: string }`）而不是纯字符串 URL 时，透传 `fetch()` 方法产生 404 错误的问题。
生成的代码现在内联解析环境供应者，并将对象环境投影到其 `.base` 属性，而不是将原始对象传递给 `makePassthroughRequest`，后者会将其字符串化为 `[object Object]`。


## 3.57.0
**`(feat):`** 在 `RealtimeClient.ConnectArgs` 上公开可选的 `protocols` 字段，用于 WebSocket 子协议协商。`ReconnectingWebSocket` 构造函数已经接受 `protocols` 参数，但它被硬编码为空数组。现在浏览器调用者可以通过子协议进行身份验证（例如 `xai-client-secret.<token>`），其中浏览器安全模型禁止自定义标头。


## 3.56.4
**`(fix):`** 从生成的 `tsconfig.base.json` 文件中删除 `baseUrl`。将 `baseUrl` 设置为 `src` 在有 `rootDir` 的情况下是不必要的，并在某些项目设置中导致意外的模块解析副作用。


## 3.56.3
**`(fix):`** 修复当为定义命名服务器（例如 `servers.production`）且具有单一 URL 环境的 AsyncAPI 规范生成 WebSocket 客户端时 TypeScript SDK 生成器崩溃的问题。Fern IR 转换器分配的 `baseUrlId` 现在对于单一 URL 环境会被静默忽略，因为只有一个 URL 可以解析。


## 3.56.2
**`(chore):`** 将 `shouldGenerateWebsocketClients` 配置选项重命名为 `generateWebSocketClients`。旧名称仍作为已弃用的后备方案被接受，以保持向后兼容性。
