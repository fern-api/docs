本页列出了 Fern 从您的文档站点发出的所有分析事件。每个表格中的**转发至**列显示哪些[已配置的提供商](/learn/docs/integrations/overview)会接收该事件 — 并非每个提供商都会接收所有事件。

<Note>
[FullStory](/learn/docs/integrations/analytics/fullstory) 和 [Intercom](/learn/docs/integrations/support/intercom) 分别提供会话录制和在线聊天功能。它们不接收下面列出的命名事件。
</Note>

## 页面浏览

| 事件 | 描述 | 转发至 |
| --- | --- | --- |
| `$pageview` | 每次路由变化时触发，包含当前 URL。 | PostHog、Segment |
| `$pageleave` | 用户离开页面时触发。 | PostHog |

页面浏览跟踪是自动的，无需额外配置。GA4 和 Google Tag Manager (GTM) 在配置后会原生处理自身的页面浏览跟踪。

## 反馈事件

这些事件由[页面反馈](/learn/docs/user-feedback)小组件和 Ask Fern 反馈组件发出。

| 事件 | 描述 | 转发至 |
| --- | --- | --- |
| `feedback_voted` | 用户点击了赞或踩按钮。 | PostHog、GA4、GTM |
| `feedback_submitted` | 用户在投票后提交了书面反馈。 | PostHog、GA4、GTM |
| `code_block_feedback_opened` | 用户打开了代码块的反馈提示。 | PostHog、GA4、GTM |
| `code_block_feedback_submitted` | 用户提交了对代码块的反馈。 | PostHog、GA4、GTM |

## API Playground 事件

这些事件跟踪 [API Explorer](/learn/docs/api-references/api-explorer) 的使用情况。

| 事件 | 描述 | 转发至 |
| --- | --- | --- |
| `api_playground_request_sent` | 用户从 API Explorer 发送了请求。 | PostHog、GA4、GTM |
| `api_playground_request_received` | API Explorer 收到了响应。 | PostHog、GA4、GTM |

## 搜索和 AI 事件

这些事件跟踪[搜索](/learn/docs/customization/search)和 [Ask Fern](/learn/docs/ai-features/ask-fern/overview) 的使用情况。

| 事件 | 描述 | 转发至 |
| --- | --- | --- |
| `ask_ai_suggest` | 生成了一条 Ask Fern 建议。 | 无（仅限 Fern 内部） |

## 错误事件

这些事件有助于识别损坏的页面和缺失的内容。

| 事件 | 描述 | 转发至 |
| --- | --- | --- |
| `not_found` | 访客访问了 404 页面。 | PostHog、GA4、GTM |

## CLI 和 Dashboard 事件

Fern CLI 和 [Dashboard](https://dashboard.buildwithfern.com) 为内部产品遥测发出自己的分析事件（命令使用、引导流程、计费事件等）。这些事件不会转发到您的分析提供商，仅供 Fern 用于产品改进。

可以通过设置 `FERN_TELEMETRY_DISABLED` 环境变量或在 `~/.fernrc` 中添加 `telemetry.enabled: false` 来禁用 CLI 遥测。
